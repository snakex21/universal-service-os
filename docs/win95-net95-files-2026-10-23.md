# RTM/OSR1 network files before static NET95 binding

The prepared 4.0.950 Windows directory lacked the original Client for
Microsoft Networks/TCP-IP files and the staged own USOSNET.SYS/INF. Importing
adapter/client bindings alone therefore did not establish working networking.

For exact source version `4 0 0 950` with NET95.REG, REG95 now calls
C:/USOS9X/NET/NFILES.BAT before changing registry attributes or importing.
The helper copies own SYS/INF to the Windows directories and materializes
51 original component files using the original source EXTRACT.EXE/CABs.
NETAPI.DLL comes from PRECOPY1.CAB; the other files use the WIN95_02 chain.
Existing Microsoft files are skipped, preserving Patcher9x changes; in
particular the helper does not replace loose NDIS or the combined VMM32.
OSR2/other versions and installs without static NET95 retain the old path.

RUN/ERR markers and checked preparation prevent successful markers or Windows
start after an interrupted/failed copy or failed registry verification.
Registry failure restores SYSTEM.DAT/USER.DAT attributes before blocking.
Helper generation failure is terminal in the target writer for this path.
All logs/markers remain beside the application on the target C: disk.
No Microsoft binary or original INF is added to the repository.

## Verification

Host tests: six network-file cases, thirteen existing REG95 cases and eleven
existing NET95 cases pass. Shell syntax and git diff --check pass.
Actual DOS R72 (RTM) and R73 (OSR1) each extracted 53 original files including
two reference INFs; sizes/hashes match the original CAB entries. R97 compared
the original RTM/OSR1 CopyFiles directives and referenced lists: identical.
This comparison does not claim that all AddReg semantics are identical.

R75 ran the generated production NFILES in actual DOS: all component files,
own installed SYS/INF and preserved existing core/inbox hashes were verified
from the closed image. It then blocked on NET95 registry failure. R90 captured
the exact reason: the test boot floppy contained OSR2 DOS4.00.1111, and the
original RTM REGEDIT refused it (Incorrect MS-DOS version).
R92 repeated the exact production NFILES/REG95 on a new qcow2 overlay using
IO.SYS, COMMAND.COM and HIMEM.SYS from that RTM target. QEMU exited85 in8.903s;
NF75.OK, REG95.OK, NFILES.OK and NET95.OK were all present, no error/RUN marker
for NFILES. Original source images were unchanged.
