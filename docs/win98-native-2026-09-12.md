# Windows 98 SE — przygotowanie z graficznego menu USOS

Poniżej zapis pierwszego wdrożenia. Późniejsza poprawka RAM i tryb naprawy:
[Windows 98 SE — RAM](win98-ram-2026-09-12.md).

Stan: 2026-09-12. Wdrożenie `B260911-232234-06A303A8` przetestowane w QEMU
do oryginalnego graficznego instalatora Windows 98. Nie jest to jeszcze
potwierdzenie pełnej instalacji do pulpitu ani test na fizycznym MS-7100.

## Obsługa

Windows → Windows 98 SE → `Windows_98_SE_PL_OEM.iso` → Automatic (DOS Setup).
Po załadowaniu źródła wybierz dysk, rozmiar 8/4/2 GiB i zatwierdź podsumowanie.
Domyślnie zaznaczone jest ANULUJ. Potwierdzenie usuwa wszystkie partycje
wybranego dysku, tworzy aktywną FAT32 i pozostawia resztę miejsca nieprzydzieloną.
Pendrive USOS nie jest oferowany jako cel. Nie trzeba wpisywać poleceń DOS.

USOS wykonuje szybkie formatowanie, a oryginalny DOS z ISO przenosi pliki
systemowe, kopiuje instalator do `C:\WIN98` i uruchamia Setup. Następnie
obsługujesz już oryginalny instalator (ENTER przy kontroli dysku, Dalej itd.).
Nie występuje restart przygotowawczy. Przy pierwszym restarcie wykonywanym
przez sam Windows uruchom komputer z dysku docelowego, wyjmując pendrive USOS.

## Implementacja

- Core czyta ISO z DATA/NTFS. Czytnik ISO9660 znajduje startową dyskietkę
  El Torito 1,44 MiB i płaski katalog WIN98. Opcjonalny TOUR jest pomijany.
- W RAM powstaje FAT16 256 MiB z oryginalnym DOS-em i 95 plikami instalatora.
  Obszar 128–384 MiB musi być dostępny według E820; typowy wymagany RAM to
  512 MiB. Nie potrzeba mikro-Linuksa ani katalogu przygotowania na WORK.
- Graficzny wybór dysku, rozmiaru i potwierdzenia działa wewnątrz USOS,
  klawiszami strzałek, ENTER i ESC. Cel musi mieć sektory 512 B i obsługę EDD.
- Przed zapisem ponownie sprawdzane są pojemność i sektor MBR. Nowa partycja
  FAT32 typu 0C zaczyna się na LBA 2048. Stare nagłówki GPT są unieważniane.
- MEMDISK 6.03 uruchamia źródło z RAM. Filtr INT 13h udostępnia DOS-owi
  wyłącznie wybrany dysk jako BIOS 80h; ukrywa pendrive i pozostałe dyski.
- Statyczny pakiet na ESP zawiera MEMDISK, licencję, manifest i źródła upstream.
  Pliki Microsoftu pochodzą z ISO użytkownika, a nie z pakietu USOS.

Obsługa dotyczy tego formatu startowego ISO Windows 98 SE i Legacy BIOS.
Nie potwierdzono innych obrazów OEM, Windows 95/98 FE/Me ani UEFI.

## Testy i dowody

Pełny `build.bat`: PASS, wraz z testami Zig i Go, audytem ISA i kontrolą
zgodności EXE/USB/Legacy Core. `tools/tests/run.ps1 -Suite all`: PASS,
w tym testy startowe UEFI x86_64 i ARM64. Nowe testy obejmują parser FAT12,
budowę RAM FAT16, plan partycji, odrzucenie zmienionego celu, FAT32 oraz
emulację filtra INT 13h i MBR w Unicorn.

Test produkcyjnego Core w QEMU: Pentium III, 2048 MiB RAM, źródło USOS jako
dysk IDE 16 GiB, pusty cel 32 GiB, brak sieci i napędu z ISO. ISO znajdowało
się wyłącznie na DATA źródłowego USOS. Z menu wybrano nową partycję 8 GiB.

1. Przed zatwierdzeniem i po ANULUJ oba dyski miały zero operacji zapisu.
2. Potwierdzenie uruchomiło formatowanie, SYS, kopiowanie i Setup bez komend.
3. ScanDisk zakończył kontrolę bez zgłoszenia błędu. Pojawił się ekran
   powitalny graficznego instalatora Windows 98.
4. Źródłowy dysk USOS przez cały przebieg miał `wr_operations=0`, `wr_bytes=0`.
5. Po wyłączeniu VM niezależny od USOS odczyt FAT32 potwierdził aktywną
   partycję, pliki DOS i 95 plików instalatora, łącznie 115683656 bajtów.
   Każdy SHA-256 był zgodny z niezależnym odczytem oryginalnego ISO.
6. Osobny start wyłącznie z dysku docelowego, bez USOS i MEMDISK, uruchomił
   DOS. Polecenie VER zwróciło `Windows 98 [Wersja 4.10.2222]`.

Artefakty lokalne w `zig-out/win98-work/`: `release-build.log`, `all-tests.log`,
`final-target2.png`, `final-confirm.png`, `final-gui.png`, `final-blockstats.txt`,
`target-verify.log`, `target-ver.png`. Test zakończono przed pełną instalacją
Windows; nie zweryfikowano jeszcze sterowników i restartów instalatora.
