## 1. What changes

Until now `tools/vista_csmwrap_prepare.sh` stopped on an NVMe target for the
x64 profile `vista-x64-sp2-uefi-csmwrap` ("No NVMe driver for 64-bit ...").
The Vista x64 CSMWrap path already runs in test mode (the installed system
gets `testsigning on` from `usos-vista-install.exe configure_boot_bios`,
because the v11 USB backport is test-signed), so a test-signed own x64 boot
driver fits the same model.

## 5. Risks for the X470

- **Signature in the PE10 x64**: Windows 10 2004 PE in test mode should take
  the SHA-1 per-build signature (QEMU did with a SHA-1 private cert); if not,
  STOP 0x7B / no disk in the PE. The user sees the "Test Mode" watermark in
  the PE.
- **Micron 3400 BAR**: usosnvme refuses a BAR above 4 GiB (Above 4G
  Decoding); the x86 runs on this board passed, so the BAR is low there.
- **DMA above 4 GiB**: 32 GB RAM, full 64-bit PRPs and
  `Dma64BitAddresses`; QEMU tested only 4 GiB.
- **pnputil / certificate** in OOBE: the x86 per-build certificate passed on
  the X470 for Vista x86; the amd64 one uses the same script.
- Server 2008 x64 shares the profile and code path, not tested.
