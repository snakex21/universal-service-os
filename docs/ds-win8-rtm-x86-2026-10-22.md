# Windows 8 RTM (NT 6.2, build 9200) x86 na ścieżce `win-x86-uefi-csmwrap` — 2026-10-22

Gałąź: `ds/win8-rtm-x86` (baza `test/x470-98se-qemu`, commit `eac23cf5`).
Zakres: 32-bitowe medium Windows 8 RTM bez firmware'owego CSM na 64-bitowym UEFI
(micro-Linux krok 610 → CSMWrap, Setup w trybie BIOS, `InstallTo`).

> **niesprawdzone na nośniku (brak ISO Win8)** — cała ścieżka jest sprawdzona
> wyłącznie statycznie/testowo: brak w laboratorium ISO Windows 8 RTM x86, więc
> nie ma przebiegu na QEMU ani na fizycznym nośniku. Fakty o nośniku
> (PE 4.0 / build 9200, brak wbudowanego stornvme) są przyjęte z dokumentacji
> Microsoft, nie zmierzone na ISO.

## 1. Co było odrzucane i co zmieniono

### 1.1 `modernSetupVersion` — `src/platform/uefi/windows_native_iso.zig`

- `src/platform/uefi/windows_native_iso.zig:462-470`: funkcja przyjmuje teraz
  trzy rodziny Setup WinPE: 6.2.9200 (Windows 8 RTM, PE 4.0), 6.3 (8.1) i 10.0.
  Tylko build 9200 dla 6.2 — przedwczesne/nieznane buildy 6.2 nadal odrzucane.
- Dotyczy obu wejść: `inspectModernIso` (x64, linia 492) i `inspectModernX86Iso`
  (x86, linia 521) — dzięki temu x86 Setup Win8 przechodzi walidację tak jak 8.1.
- Test (linia 472-480) był negatywny dla 9200, jest pozytywny:
  `6.2.9200 → true`, `6.3.9600 → true`, `10.0 → true`;
  negatywne zostają `6.2.8400`, `6.1.7601`, `6.0.6002`.

### 1.2 `supported_nt` — `tools/windows_nvme_modern.cmd`

- `tools/windows_nvme_modern.cmd:51-58`: bramka wersji przyjmuje
  `6.2` + build `9200` (Windows 8 RTM) obok dotychczasowych `6.2/9600`,
  `6.3/9600` i `10.0/10240-21999`. Komentarz mówił „do not admit Windows 8” —
  zaktualizowany.
- Nagłówek pliku (linia 3): „Opt-in 8 RTM / 8.1 / 10 x86 only.”.
- Wybór sterownika: NVMe dla Win8 RTM idzie przez ten sam pakiet „modern”
  (`usosnvme.inf/.sys/.cat/.cer` + helper `usos-nvme-modern.exe`, DISM
  `/ForceUnsigned`, wpisy boot-start w SYSTEM i WinRE) — 32-bitowy Windows nie
  wymusza podpisu sterownika, więc brak podpisu Microsoft nie jest przeszkodą.
  Żadna inna gałąź wyboru sterownika nie zależy od wersji NT: ścieżka
  `:nvme` w `tools/windows_x86_csmwrap.cmd:512-515` wychodzi na
  `usos-nvme-modern.flag`, a nie-modern fallback (linia 517) obsługuje tylko
  6.0/6.1 i nigdy nie dotyczy Windows 8.

### 1.4 Routing: Windows 8 musi w ogóle dojść do tej ścieżki

> **Przegląd przed mergem (2026-10-22): zmiana routingu wycofana, zastąpiona
> bramką.** Regenerowany golden zmieniał nie tylko `windows-8`, lecz także
> `windows-server-2012` (`route_as = "windows-8"`): x64 Win8 i Server 2012 na
> UEFI szłyby z kopii WORK (`iso-work-chainload`) na nieuruchomiony nigdy
> natywny start `win10-11-uefi-native` z PE 4.0, z etykietą `TESTED IN VM`
> bez żadnego testu. Zamiast tego: `windows-8` ma `native_uefi = .none` (routing
> i `routing_golden.tsv` bez zmian) i nową cechę `x86_csmwrap = true`
> (`src/catalog/os_profiles.zig`); `manual_images.x86Csmwrap` ją akceptuje, a
> `manual_images.backendFor` podmienia backend na `windows_iso` tylko dla
> 32-bitowego nośnika Win8 przy Automatic na 64-bitowym UEFI bez CSM.
> `modernSetupVersion` (start natywny x64) zostaje 6.3/10; 6.2.9200 przyjmuje
> tylko `modernX86SetupVersion` (`inspectModernX86Iso`). Server 2012 nie ma
> nośników x86, więc nic się dla niego nie zmienia. Poniższy opis to pierwotna
> wersja gałęzi.

Ścieżka `win-x86-uefi-csmwrap` jest wybierana tylko dla systemów
`native_uefi = .modern` (`src/platform/uefi/manual_images.zig:69-76`,
`src/platform/uefi/manual_summary.zig:433` wymaga backendu `windows_iso`).
Windows 8 miał `native_uefi = .none` i trafiał na `iso-work-chainload`, więc
żadna z trzech bramek nie była nawet osiągana. Zmiany:

- `src/catalog/os_profiles.zig:108-116`: `.{ .system_id = "windows-8",
  .native_uefi = .modern }` (komentarz opisuje PE 4.0 / PE 5.0 i ścieżkę x86).
- `src/catalog/os_profiles.zig:410-414`: Windows 8 (i Server 2012 przez
  `route_as`) zachowuje na BIOS-ie kopię WORK — `win81-bios-chainload`
  (automatic) i `win81-bios-other-iso` (jawny `direct_iso` → brak backendu,
  jak dla 8.1). Zachowanie BIOS bez zmian.
- `src/flow/testdata/routing_golden.tsv`: regeneracja
  (`USOS_UPDATE_GOLDEN=1 zig build test`); diff obejmuje **wyłącznie** wiersze
  `windows-8` (route/profile/resolve/menu/help, 35 insertions / 22 deletions),
  m.in. `windows-8 iso automatic uefi` → `win10-11-uefi-native` /
  `windows_iso`/`direct_iso`, a menu: `Automatic (ISO) [TESTED IN VM]`.
- `src/flow/preparation_capability.zig:189`: test oczekuje teraz
  `nativeUefiIso("windows-8")`.
- `src/flow/boot_method_help.zig:119-133`: Windows 8 dołączony do testu pomocy
  „native start, nic nie kopiowane do WORK”; test „explicit ISO help explains
  WORK preparation” sprawdza teraz Vistę (Windows 8 nie ma już kopii WORK).

## 2. Folder DATA, dawca PE10, ekran

- **Folder danych**: `Systems\Windows\Windows 8` — dokładnie ta nazwa, której
  USOS już używa (`tools/windows_setup_media.sh:25,40`;
  `categoryForFolder` w `usos-source.ini`/request.ini).
- **Dawca PE10 x86**: `src/platform/uefi/windows_native_iso.zig:545-556`
  (`modernX86ExternalDonor`) przyjmuje 6.2/9200 dla folderu `Windows 8`
  (i nadal 6.3 dla 8.1 / Embedded 8.1); wymagane jest jednocześnie
  `nvme_on` i brak `Unattended/nvme-off.txt` (linia 631). To ten sam dawca co
  dla 8.1: Windows 10 x86 Setup ISO z DATA (`formatX86CsmwrapRequest`,
  `donor=`), używany **tylko** dla celu NVMe — cel SATA zostaje przy własnym
  PE 4.0 z ISO (bramka dysku w prepare.sh).
- **Ekran/rozdzielczość**: bez zmian w kodzie, bo polityka jest już
  wersjonozależna od `X86_SELF`, nie od folderu:
  `tools/vista_csmwrap_target.sh:172-178` (32-bit 8 / 8.1 / 10 → Microsoft
  Basic Display/DisplayOnly 1024x768) i rejestracja `\USOS\NT6\USOSRES.EXE`
  w `HKCU\...\Run` użytkownika Default
  (`tools/windows_x86_csmwrap.cmd:104-110`, `windows_display_register.h`);
  rejestracja nie sprawdza wersji NT, więc Windows 8 dostaje USOSRES tak samo
  jak 8.1/10.
- **Narzędzia Setup/instalacji**: `tools/windows_installto.h:117,180` już
  klasyfikuje „modern (Setup 6.2+, i.e. 8.x / 10)”, a usosmpart/`nodump`
  w `tools/windows_x86_csmwrap.cmd:453,642-653` obejmują NT 6.2 z budową 9200
  (modern-flag nie wyłącza usosmpart poniżej 15063) — bez zmian.

## 4. Czego nie sprawdzono

- **niesprawdzone na nośniku (brak ISO Win8)** — brak przebiegu Setup z ISO
  Windows 8 RTM x86 (QEMU i sprzęt), brak weryfikacji, że PE 4.0 z ISO
  faktycznie startuje pod CSMWrap i że `usosnvme` wiąże kontroler NVMe
  (X470/Micron) po pierwszym restarcie.
- Nie sprawdzono WinRE Windows 8 (DISM `/Add-Driver` do `winre.wim` 6.2) —
  brak obrazu.
- Nie sprawdzono zachowania Windows 8 x64 na natywnym starcie UEFI: po zmianie
  routingu x64 ISO Win8 idzie przez `win10-11-uefi-native` (wimboot), co jest
  konsekwencją `native_uefi = .modern`, ale nie było testowane na ISO (tylko
  golden/menu/help).
- Nie uruchamiano `build.bat` do końca (micro-Linux HTTP 404), więc pełny
  release (payload, podpisy) nie powstał; helper `usos-nvme-modern.exe` nie
  został zbudowany w tym worktree.
- `no_inbox_nvme` dla `windows-8` pozostawione bez zmian (`false`, jak dotąd);
  flaga dotyczy tylko noty w podsumowaniu, nie wyboru sterownika.
