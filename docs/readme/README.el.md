<a id="what-usos-is"></a>
## 1. Τι είναι το USOS

Το USOS είναι ένα στικ USB για την εγκατάσταση και εκκίνηση λειτουργικών
συστημάτων, από το MS-DOS έως τα Windows 11 και το Linux, σε υπολογιστές
με BIOS και UEFI, συμπεριλαμβανομένου του UEFI με Secure Boot. Αντιγράφετε
τις δικές σας εικόνες ISO στο στικ σαν κανονικά αρχεία· το USOS σάς δίνει
ένα μενού, ρητή και προστατευμένη επιλογή του δίσκου προορισμού, καθώς και
τα προγράμματα οδήγησης και τις διορθώσεις που χρειάζονται τα παλιά
συστήματα σε νέο υλικό. Το στικ προετοιμάζεται στα Windows με το
`USOS-Installer-1.0.0.exe`. Το USOS δεν περιλαμβάνει εικόνες Windows,
κλειδιά προϊόντος ούτε τρόπο παράκαμψης της ενεργοποίησης.

<a id="features"></a>
## 2. Δυνατότητες

- **Ένα μενού, BIOS και UEFI.** Το ίδιο στικ ξεκινά σε Legacy BIOS και σε
  UEFI (x64) με τον ίδιο κατάλογο. Το μενού UEFI λειτουργεί με
  πληκτρολόγιο, ποντίκι, αφή και χειριστήρια USB.
- **Οι εικόνες παραμένουν αρχεία.** Οι εικόνες ISO, WIM, IMG, VHD, VHDX και
  EFI διαβάζονται απευθείας από το διαμέρισμα NTFS DATA· τίποτα δεν
  αποσυμπιέζεται και τίποτα δεν χρειάζεται να εκτελεστεί μετά την
  αντιγραφή.
- **Προστατευμένος δίσκος προορισμού.** Εσείς επιλέγετε και επιβεβαιώνετε
  πάντα τον δίσκο· το ίδιο το στικ USOS δεν προτείνεται ποτέ.
- **Secure Boot** μέσω του shim 16.1 (υπογεγραμμένο από τη Microsoft) και
  του κλειδιού USOS (MOK), που καταχωρίζεται μία φορά ανά υπολογιστή.
- **Παλιά Windows σε νέο υλικό.** Windows XP με πακέτο προγραμμάτων
  οδήγησης και PAE σε UEFI με CSM· XP και Vista σε UEFI χωρίς CSM μέσω
  CSMWrap (πειραματικό)· Windows 7 x64 χωρίς CSM μέσω UefiSeven και ενός
  διεκπεραιωτή δρομολόγησης VGA· ενσωμάτωση USB 3 και NVMe για Windows 7.
- **Προφίλ απαντήσεων** για αυτόματες εγκαταστάσεις Windows και Linux,
  που επεξεργάζονται στο μενού UEFI με πληκτρολόγιο οθόνης.
- **Εικόνες ISO Linux από το DATA** (Ubuntu, Mint, Fedora, Debian,
  SystemRescue, GParted, Clonezilla και άλλες), σε UEFI με και χωρίς Secure
  Boot και σε BIOS.
- **Εργαλεία:** ενσωματωμένο FreeDOS με διαχειριστή αρχείων και πίνακα
  Hardware & SMART (BIOS), το κέλυφος UEFI του EDK2 (UEFI), τα δικά σας
  εκκινήσιμα εργαλεία στο `Utilities`, τα δικά σας προγράμματα οδήγησης
  UEFI και φάκελοι προγραμμάτων οδήγησης INF για Windows.
- **Πρόγραμμα εγκατάστασης με τέσσερις λειτουργίες:** Εγκατάσταση, Τοπική
  ενημέρωση (**Ενημέρωση USOS**, διατηρεί τις εικόνες και τα αρχεία σας),
  Επισκευή (**Επισκευή ESP**), Απεγκατάσταση.
- **27 γλώσσες** (τα αγγλικά είναι η γλώσσα αναφοράς· οι υπόλοιπες, εκτός
  από τα πολωνικά, επισημαίνονται ως μερικώς ή πλήρως αυτόματα
  μεταφρασμένες), θέματα με επεξεργαστή μέσα στο μενού, υποστήριξη αφής και
  χειριστηρίου στο ROG Ally.

## 3. Υποστηριζόμενα συστήματα και λειτουργίες υλικολογισμικού

**HW** = δοκιμασμένο σε πραγματικό υλικό, **VM** = δοκιμασμένο μόνο σε
QEMU/VirtualBox, **πειρ.** = πειραματικό (επισημαίνεται ως τέτοιο στο
μενού), **μη δοκιμασμένο** = η διαδρομή υπάρχει αλλά δεν έχει καταγραφεί
καμία εκτέλεση, **—** = δεν υποστηρίζεται (το μενού δείχνει τον λόγο).
Μηχανήματα δοκιμών: **X470** (ASRock X470, Ryzen 7 5700X, Radeon RX 560,
UEFI), **MS-7100** (MSI, Socket 939, Athlon 64 X2, BIOS), **Ally** (ASUS
ROG Ally RC71L, UEFI με Secure Boot).

|---|---|---|---|---|

| Windows 2000 SP4 | HW (MS-7100) | πειρ., VM (έως την αντιγραφή αρχείων) | πειρ., VM (CSMWrap) | — |

## 4. Γρήγορη εκκίνηση

Αρχεία της έκδοσης:

| Αρχείο | Σκοπός |
|---|---|
| `USOS-Installer-1.0.0.exe` | το πρόγραμμα εγκατάστασης· περιέχει ολόκληρο το USOS |
| `USOS-1.0.0-WinPE-PE10-donor.zip` | δότης PE10, απαραίτητος για τα Vista και τα αρχικά ISO των Windows 7 σε UEFI |
| `USOS-1.0.0-XP-package-PL.zip`, `USOS-1.0.0-XP-package-EN.zip` | πακέτο UEFI για Windows XP x86 SP3, το καθένα για ακριβώς ένα αρχικό ISO (`pl_..._x14-80476.iso` / `en_..._x14-80428.iso`), εγκαθίσταται με το συμπεριλαμβανόμενο `install-xp-package.ps1` |
| `USOS-1.0.0-sources.zip` + `SOURCE-OFFER.txt` | πηγαίος κώδικας των στοιχείων τρίτων και η γραπτή προσφορά πηγαίου κώδικα |
| `USOS-1.0.0-buildkit.zip` | καθορισμένες εκδόσεις εργαλείων και είσοδοι build για επαναδημιουργία χωρίς σύνδεση |
| `LICENSES/`, `THIRD-PARTY-NOTICES.txt` | κείμενα αδειών και ειδοποιήσεις |
| `SHA256SUMS` | SHA-256 κάθε αρχείου |

Ελέγξτε ένα ληφθέν αρχείο με `certutil -hashfile USOS-Installer-1.0.0.exe SHA256`
(ή `Get-FileHash` στο PowerShell) σε σύγκριση με το `SHA256SUMS`.

![Πρόγραμμα εγκατάστασης USOS: επιλογή λειτουργίας](../images/installer-mode.png)

1. Πάρτε ένα στικ USB **τουλάχιστον 32 GiB** (στην πράξη 64 GB· ένα στικ
   που πωλείται ως «32 GB» είναι συνήθως πολύ μικρό). **Όλα τα δεδομένα
   του θα διαγραφούν.**
2. Σε έναν υπολογιστή με Windows εκτελέστε το `USOS-Installer-1.0.0.exe`
   (ζητά δικαιώματα διαχειριστή), επιλέξτε **Εγκατάσταση**, διαλέξτε το
   στικ, πληκτρολογήστε το κείμενο επιβεβαίωσης και πατήστε **ΔΙΑΓΡΑΦΗ ΚΑΙ
   ΕΓΚΑΤΑΣΤΑΣΗ**.
3. Αντιγράψτε τις εικόνες ISO στο διαμέρισμα DATA, στον φάκελο `Images`
   κάθε συστήματος, π.χ. `Systems\Windows\Windows 11\Images\`.
4. Προαιρετικά: για Vista ή αρχικά Windows 7 σε UEFI, αντιγράψτε τον φάκελο
   `Programs` από το zip του δότη PE10 στη ρίζα του DATA και εκτελέστε
   **Ενημέρωση USOS**· για XP σε UEFI, εκτελέστε ως διαχειριστής το
   `install-xp-package.ps1` από το πακέτο XP που αντιστοιχεί στο ISO σας
   (ένα πακέτο κάθε φορά).
5. Εκκινήστε τον υπολογιστή προορισμού από το στικ (BIOS ή UEFI). Με
   ενεργό Secure Boot, καταχωρίστε μία φορά το κλειδί USOS
   ([Secure Boot](#secure-boot)). Επιλέξτε το σύστημα και την εικόνα,
   προαιρετικά ένα προφίλ απαντήσεων, επιβεβαιώστε τον δίσκο προορισμού και
   ακολουθήστε το πρόγραμμα εγκατάστασης του συστήματος.

Οδηγίες βήμα προς βήμα για κάθε οθόνη υπάρχουν στον οδηγό
χρήσης: [English](../USER-GUIDE.en.md), [Polski](../USER-GUIDE.pl.md).

<a id="data-layout"></a>
## 5. Δομή φακέλων στο DATA

Το πρόγραμμα εγκατάστασης δημιουργεί στο στικ τρία διαμερίσματα:
`USOS_ESP` (FAT32, 1 GiB: αρχεία εκκίνησης, κλειδί, ρυθμίσεις,
αρχεία καταγραφής, προφίλ), `USOS_DATA` (NTFS: τα αρχεία σας) και
`USOS_WORK` (NTFS, χώρος εργασίας για ορισμένα προγράμματα εγκατάστασης
Windows). Όλοι οι φάκελοι στο DATA δημιουργούνται αυτόματα:

```
USOS_DATA\
├─ Systems\
│  ├─ Windows\<έκδοση>\     Images\  Unattended\   (Windows 3.1 έως 11, Server 2003-2025)
│  ├─ Linux\<διανομή>\      Images\  Unattended\   (Other Linux\ για άγνωστα ISO)
│  ├─ Betas\
│  └─ DOS\<παραλλαγή>\      Images\
├─ Utilities\
│  ├─ FreeDOS\Programs\     προγράμματα DOS για το ενσωματωμένο FreeDOS
│  ├─ UEFI Shell\Tools\     εργαλεία EFI για το κέλυφος UEFI
│  └─ <εργαλείο σας>\Images\   π.χ. MemTest86\Images\memtest86.efi
├─ Drivers\
│  ├─ UEFI\<όνομα>\         προγράμματα οδήγησης .efi που φορτώνει το μενού USOS
│  └─ <έκδοση Windows>\     Storage\  USB\  Other\  (πακέτα INF)
├─ Themes\<όνομα>\theme.ini τα δικά σας θέματα (μενού UEFI)
└─ Programs\
   └─ USOS\                 διαχειρίζεται το USOS (δότης PE10), μην το αγγίζετε
```

Μετά την προσθήκη ενός `icon.png` ή ενός νέου φακέλου εργαλείου, εκτελέστε
**Ενημέρωση USOS**. Το πλήρες δέντρο βρίσκεται στον
[οδηγό χρήσης, ενότητα 4](../USER-GUIDE.en.md#4-folder-layout-on-data)
(στα αγγλικά).

<a id="secure-boot"></a>
## 6. Secure Boot

Με ενεργό Secure Boot, το USOS ξεκινά μέσω του **shim 16.1** (build του
Fedora, υπογεγραμμένο από τη Microsoft UEFI CA) και του MokManager. Το ίδιο
το USOS και τα στοιχεία του είναι υπογεγραμμένα με το **κλειδί USOS**, που
καταχωρίζεται **μία φορά ανά υπολογιστή**:

- **Ο ευκολότερος τρόπος:** απενεργοποιήστε το Secure Boot, εκκινήστε από
  το στικ, επιλέξτε **Προσθήκη** στην αρχική οθόνη και επιβεβαιώστε με
  **Ναι, αποθήκευση κλειδιού**, και μετά ενεργοποιήστε ξανά το Secure Boot.
  Λειτουργεί και σε Setup Mode (επιβεβαιωμένο στο X470).
- **Με το Secure Boot ενεργό:** στην οθόνη «Verification failed»
  χρησιμοποιήστε στο MokManager -> **Enroll key from disk** -> `USOS_ESP`
  -> `USOS-KEY.cer` (επιβεβαιωμένο στο ROG Ally). Η κάρτα **Προετοιμασία
  (μία φορά)** του προγράμματος εγκατάστασης κάνει το MokManager να
  περιμένει αντί να κάνει αντίστροφη μέτρηση.

Η επαναφορά της NVRAM αφαιρεί το κλειδί· καταχωρίστε το ξανά. Τα XP, Vista,
7, κάθε διαδρομή CSMWrap, το SystemRescue και τα εργαλεία που ξεκινούν από
το κέλυφος UEFI χρειάζονται απενεργοποιημένο Secure Boot. Ο πυρήνας δεν
είναι ακόμη κλειδωμένος (στοιχείο N6 του οδικού χάρτη), οπότε η καταχώριση
του κλειδιού USOS σημαίνει εμπιστοσύνη σε οτιδήποτε έχει υπογραφεί με αυτό.
Λεπτομέρειες:
[οδηγός χρήσης, ενότητα 6](../USER-GUIDE.en.md#6-secure-boot-and-the-usos-key-mok)
(στα αγγλικά), [secure-boot-usos.md](../secure-boot-usos.md).

<a id="answer-profiles"></a>
## 7. Προφίλ απαντήσεων

Ένα μικρό προφίλ (λογαριασμοί, όνομα υπολογιστή, γλώσσα, ζώνη ώρας,
προαιρετικές ρυθμίσεις) μετατρέπεται κατά την εκκίνηση σε `WINNT.SIF`
(2000/XP/2003), `autounattend.xml` (Vista έως 11, Server) ή σε Ubuntu
autoinstall, Debian preseed ή Fedora kickstart. Τα προφίλ δημιουργούνται
στο μενού UEFI (**Αυτόματη εγκατάσταση** -> **+ Προσθήκη νέου προφίλ**)
και αποθηκεύονται στο ESP.

![Επεξεργαστής προφίλ απαντήσεων, ενότητα «Εμφάνιση και πρόσθετα»](../images/profile-editor-appearance.png)

- Ο δίσκος προορισμού **επιλέγεται πάντα χειροκίνητα**· ένα προφίλ δεν
  επιλέγει ούτε διαγράφει ποτέ δίσκο.
- Ένα κλειδί προϊόντος αποθηκεύεται μόνο αν τσεκάρετε «Απομνημόνευση του
  κλειδιού σε αυτό το στικ»· διαφορετικά διατηρείται μόνο μέχρι την
  επανεκκίνηση. **Το USOS δεν περιλαμβάνει κλειδιά** και δεν παρακάμπτει
  την ενεργοποίηση ούτε τη σελίδα του κλειδιού προϊόντος.
- Οι κωδικοί πρόσβασης και τα απομνημονευμένα κλειδιά αποθηκεύονται στο
  στικ ως απλό κείμενο (δεν εμφανίζονται ποτέ σε λίστες ή αρχεία
  καταγραφής). Τα προφίλ Linux λειτουργούν μόνο σε UEFI.

Λεπτομέρειες: [οδηγός χρήσης, ενότητα 7](../USER-GUIDE.en.md#7-answer-profiles-and-tweaks)
(στα αγγλικά), [answer-profiles.md](../answer-profiles.md).

<a id="known-issues"></a>
## 8. Γνωστά ζητήματα

- **Vista σε μητρικές μόνο με USB 3 (X470):** τα στικ USB δεν είναι ορατά
  στο εγκατεστημένο σύστημα και τα Vista παραμένουν σε λειτουργία δοκιμής
  (backport USB 3 με υπογραφή δοκιμής). Μια κάρτα PCIe Renesas uPD72020x
  αποτρέπει και τα δύο.
- **Διαδρομές CSMWrap:** χρειάζονται κάρτα γραφικών με legacy VBIOS
  (διαφορετικά μαύρη οθόνη), δεσμεύουν ένα νήμα CPU, χρειάζονται δίσκο
  προορισμού MBR (διαγράφεται) και απενεργοποιημένο Secure Boot.
- **Server 2003 x86 / XP x64:** STOP 0xA5 (ACPI) στο X470 και καμία είσοδος
  USB σε μητρικές μόνο με xHCI.
- **Τα Windows 2000** δεν λειτουργούν σε μητρικές μόνο με AHCI (δεν υπάρχει
  πρόγραμμα οδήγησης AHCI για NT 5.0)· **τα XP** δεν υποστηρίζουν NVMe και
  σε λειτουργία BIOS δεν λαμβάνουν πακέτο προγραμμάτων οδήγησης ούτε PAE.
- **Secure Boot:** το SystemRescue μπλοκάρεται (δεν υπάρχει υπογεγραμμένος
  φορτωτής)· το κέλυφος UEFI δεν μπορεί να εκκινήσει εργαλεία· μετά την
  ενημέρωση DBX για το BlackLotus, παλαιότερα μέσα Windows δεν ξεκινούν.
- **Linux:** το πρόγραμμα εγκατάστασης του Ubuntu Server προεπιλέγει τον
  μεγαλύτερο δίσκο, που μπορεί να είναι το στικ USOS· ελέγχετε πάντα τον
  προορισμό.
- **Το υλικολογισμικό AMI** εμφανίζει κάθε διαμέρισμα του στικ ως ξεχωριστή
  καταχώριση εκκίνησης.
- Το βοηθητικό micro-Linux χρειάζεται CPU x86-64 και τουλάχιστον 256 MiB
  RAM.

Η πλήρης λίστα με τις λύσεις παράκαμψης, καθώς και η ειλικρινής λίστα όσων
**δεν έχουν δοκιμαστεί** ακόμη σε υλικό (π.χ. Windows Server 2008-2025,
Windows 8/8.1, Windows 10/11 με Secure Boot σε υλικό, το αρχικό ISO των
Windows 7 SP1 μέσω του δότη PE10), βρίσκονται στις
[σημειώσεις έκδοσης](../release-notes-1.0.md#known-issues) (στα αγγλικά)
και στον [οδηγό χρήσης, ενότητες 9 και 10](../USER-GUIDE.en.md#9-known-issues-and-workarounds)
(στα αγγλικά).

<a id="building"></a>
## 9. Μεταγλώττιση από τον πηγαίο κώδικα

Η μεταγλώττιση γίνεται στα Windows. Πλήρεις οδηγίες:
[BUILDING.md](../BUILDING.md) (στα αγγλικά).

- Το `build.bat` δημιουργεί ολόκληρη την έκδοση (πρόγραμμα EFI,
  micro-Linux, πυρήνα BIOS, payload και `installer\USOS Installer.exe`) με
  ένα αναγνωριστικό build (`BYYMMDD-HHMMSS-XXXXXXXX`). Χρησιμοποιείται το
  φορητό Zig στο `tools/zig`· τα Go και Python πρέπει να βρίσκονται στο
  `PATH`.
- Το `tools/tests/run.ps1` εκτελεί τις αυτόματες δοκιμές, π.χ.
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/tests/run.ps1 -Suite all`.
- Το `powershell -ExecutionPolicy Bypass -File tools\release\make_release.ps1`
  παράγει τα αρχεία της έκδοσης στο `zig-out\release-1.0\`.
- **Μεταγλώττιση χωρίς σύνδεση:** αποσυμπιέστε το `USOS-1.0.0-buildkit.zip`,
  ορίστε το `USOS_BUILDKIT` στον αποσυμπιεσμένο φάκελο `USOS-1.0.0-buildkit`
  και εκτελέστε το `build.bat`· το κιτ ελέγχεται με βάση το manifest του
  και οι λήψεις είναι απενεργοποιημένες.
- **Κλειδί υπογραφής:** το κλειδί Secure Boot (MOK) βρίσκεται **εκτός του
  αποθετηρίου**, στο `%APPDATA%\USOS\signing\` (το `USOS_SIGNING_DIR` το
  παρακάμπτει). Χωρίς αυτό το build είναι **χωρίς υπογραφή** και εκκινεί
  μόνο με απενεργοποιημένο Secure Boot. Μην κάνετε ποτέ commit και μην
  μοιράζεστε το κλειδί.

Οι εικόνες ISO των Windows, τα προγράμματα οδήγησης και άλλα μέσα τρίτων
δεν αποτελούν ποτέ μέρος του αποθετηρίου.
