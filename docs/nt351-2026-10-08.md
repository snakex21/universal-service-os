# Windows NT 3.51 Workstation / Server without CSM (2026-10-08)

Profile `nt3-x86-qemu-csmwrap` (experimental, UEFI only). The NT 4.0 flow
(docs/nt4-2026-10-07.md) with the NT 3.51 CD: UEFI menu, micro-Linux step
620, the whole install in QEMU on the target PC, automatic restart, then the
target disk's CSMWrap entry starts the finished system.

## What the user needs on USOS_DATA

| What | Where |
|---|---|
| NT 3.51 Workstation CD | `Systems\Windows\Windows NT 3.51\Images\*.iso` |
| NT 3.51 Server CD | `Systems\Windows\Windows NT 3.51 Server\Images\*.iso` |

No product key: the 3.51 `INITIAL.INF` has `DisplayPidDlg = NO`, so neither
the menu nor GUI Setup asks for one. No service pack: SP5 for NT 3.51 is not
available here, so the RTM system is installed (it starts on Zen 3, QEMU
EPYC-Milan 2026-10-08). Microsoft files are never on the stick or in git.

## Flow

1. UEFI menu: `answer_profiles.stageWin9x` renders `EFI\USOS\answer\NT351.SIF`
   / `NT351S.SIF` (`src/flow/answer/nt3.zig`); `request.ini` as for 9x/NT4.
   Without a profile micro-Linux writes the same default answer itself
   (`w9x_nt3_default_sif` in `tools/w9x_csmwrap_prepare.sh`; both pinned to
   `src/flow/answer/testdata/golden/default.windows-nt-3-51.WINNT.SIF`).
2. micro-Linux (`tools/w9x_csmwrap_prepare.sh`, tags `NT351` / `NT351S`):
   the NT 4.0 branch without the SP6a lookup and the key check; the target
   script runs with `NT_MAJOR=3` and refuses a CD whose `TXTSETUP.SIF`
   `[SetupData] MajorVersion` is not 3 (and `MinorVersion` not 51).
3. `tools/nt4_csmwrap_target.sh` writes the winnt /b layout on a FAT16 C:
   (as NT4) with the NT 3.51 differences below and `\USOS\NT3`
   (AHCINT, usosrst, usosusb NT 3.51 builds, `USOSNT3.EXE`).
4. `tools/nt4_qemu_install.sh` runs the VM until `\USOS\NT3\DONE.TXT`, then
   BOOT.INI, cleanup and the CSMWrap ESP as for NT4.

## WINNT.SIF (CR LF)

```
[Data]           MsDosInitiated = 1, Floppyless = 1
[Unattended]     Method = express, ConfirmHardware = no, NtUpgrade = no,
                 Win31Upgrade = no, TargetPath = \WINNT,
                 OverwriteOemFilesOnUpgrade = no
[GuiUnattended]  !SetupNetwork = NO, !SetupApplications = NO,
                 ;USOS-TZ=<9x zone key>   (micro-Linux: !TimeZone per CD language)
[UserData]       !FullName, !OrgName, !ComputerName
empty [LicenseFilePrintData], [NetworkAdapterData], [TransportData], [DomainData]
```

The GUI-mode keys of NT 3.51 (`INITIAL.INF`) carry a `!` prefix. No
`ProductId`, no `OemPreinstall` (NT 3.51 has no `CMDLINES.TXT`, no RunOnce,
no REGEDIT4 import), no HAL pin, no `[Display]` (VGA only, 640x480x16; no
VESA driver for NT 3.51 yet).

micro-Linux adds:

- `[GuiUnattended] !DetachedProgram = "C:\USOS\NT3\USOSNT3.EXE"` with
  `!Arguments = "/setup"` (`nt3_detached_answer`): GUI Setup starts it early;
  it registers the one-shot USOS service that, at the first start of the
  installed system, copies and registers the drivers, turns atdisk/atapi off,
  writes VERSION.TXT / DRIVERS.TXT / DONE.TXT and restarts. The awk program
  keeps the backslashes (`\\U` in the awk string; commit cc57862).
- Server CD (`TXTSETUP.SIF ProductType` not 0): `!AdvServerType = SERVERNT`
  and `!AutoMode = PerServer`, `!AutoUsers = 5` (`nt4_server_answer` with the
  NT 3.51 prefix, also into the empty `[LicenseFilePrintData]`). The CD
  decides, not the menu entry; NT 3.51 Server uses the same flow.

## Root causes found on the way

1. **STOP 0x50 (CR2 FFBC3014) in text-mode Setup**, QEMU on any CPU model:
   the NT 3.51 loaders turn every E820 entry, reserved ones included, into a
   memory descriptor; the 3.51 kernel takes `MmHighestPhysicalPage` from the
   highest one (SeaBIOS FFFC0000 -> 0xFFFFF) while the PFN database covers
   RAM only, so `MiInitMachineDependent` faults on the first PTE that maps
   device memory. Fix: `src/platform/bios/nt3/nt3_e820_mbr.S` (own GPL), the
   XP geometry-fix MBR plus a resident INT 15h hook (1 KiB under the INT 12h
   top) that hides entries above 4 GiB and non-RAM entries at or above 1 MiB,
   clips RAM at 4 GiB and ends the low RAM entry below the hook. Built by
   `tools/build_xp_geometry_fix_mbr.ps1` as `nt3-e820-mbr-440.bin`, shipped
   in micro-Linux as `/usr/lib/usos/nt3-e820-mbr-440.bin`.
2. **STOP 0x6B (C000003A)**: NT 3.51 CDs have no `I386\SYSTEM32`; winnt.exe
   builds `~BT\SYSTEM32` from DOSNET `[FloppyFiles.1]` (ntdll.dll, usetup.exe
   as smss.exe). The target script does the same.
3. **autochk "Setup was unable to verify your C: drive ... Press ENTER to
   continue"**: answered by the VM runner (`W9X_VM_TEXT_ANSWER=ret` on an idle
   text screen, set by `nt4_qemu_install.sh` when `\USOS\NT3` exists).
4. **Post-install work**: no RunOnce/CMDLINES.TXT on NT 3.51, hence
   `!DetachedProgram` + the USOSNT3 service (above).

## Limits

- PS/2 keyboard; display 640x480 (VGA).
- No service pack (SP5 not available); NT 3.5 and 3.1 CDs are refused.
- Hardware test on the X470 pending.

Tests: `tools/tests/test_nt3_flow.py`, `src/flow/answer/nt3.zig`,
`src/catalog/os_profiles.zig` (routing), `src/flow/testdata/routing_golden.tsv`.
