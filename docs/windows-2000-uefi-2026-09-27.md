# Windows 2000 on the USOS paths: BIOS, UEFI + CSM, UEFI without CSM (2026-09-27)

Status: **experimental**. BIOS is the existing path (unchanged). From UEFI,
Windows 2000 now uses the XP UEFI-CSM preparation (micro-Linux, package
`EFI\USOS-XP`), and without a firmware CSM the CSMWrap ESP of
[design/csmwrap-integration.md](design/csmwrap-integration.md). Design context:
[design/nt5-uefi-family.md](design/nt5-uefi-family.md) section 3.1.

## 1. Paths

| Path | Profile | What runs | Status |
|---|---|---|---|
| BIOS | `nt5-staging` (action `windows2000-staging`) | BIOS Core -> micro-Linux NT5 staging | unchanged; confirmed earlier (MS-7100, VirtualBox) |
| UEFI + CSM | `w2k-x86-sp4-uefi-csm` (new) | UEFI menu -> `EFI\USOS-XP\vmlinuz.efi` + `initramfs-xp` + `lang.cpio`, action `windows2000-staging` | QEMU PASS (text-mode copy) |
| UEFI, no CSM | same + `usos.xp_boot=csmwrap` | as above, plus the CSMWrap ESP at the disk end (`xp_csmwrap_esp.sh`) | QEMU PASS (OVMF without CSM -> CSMWrap -> text mode -> restart -> second CSMWrap boot) |

Not on the X470 yet (see section 3: no AHCI driver).

## 2. What is shared and what differs from XP

Shared (no copy of the code): the UEFI start (`xp_preparation.zig`, now
`Nt5System` -> action + profile), pipeline step 100, `legacy_xp_staging.sh`,
the disk guard, the single-volume NTFS plan (128 GiB cap), the NT52 boot
sector, the local source copy, DOSNET aliases, the 2000 media markers
(`prepare_nt5_media_markers.sh`), usos-xp.ini / answer profiles, the
read-only zero-file verification and the CSMWrap ESP.

The micro-Linux side tests one predicate, `usos_nt5_uefi_profile`
(`tools/nt5_profile.sh`), instead of the XP profile id. Windows 2000 then
differs only where the system does:

| | XP (xp-x86-sp3-uefi-csm) | 2000 (w2k-x86-sp4-uefi-csm) |
|---|---|---|
| Driver bundle | GenAHCI + StorPort, KMDF, USB3, community ACPI | **none** (section 3) |
| Automatic answer | `xp_selected_partition_uefi_csm.sif` | `w2k_selected_partition_uefi_csm.sif` |
| Install dir | `\WINDOWS` | `\WINNT` |
| Key in usos-xp.ini / profile | `[UserData] ProductKey` | `[UserData] ProductID` (the staged system decides when usos-xp.ini has no `family=`) |
| Setup end | `pae.exe` (PAE, accounts, crash dump off) | `C:\USOS\W2K\usos-setup.cmd` via `[SetupParams] UserExecute`: creates the usos-xp.ini accounts, then deletes them |
| PAE | `pae.exe` | none: 2000 Professional is limited to 4 GB (see nt5-uefi-family.md section 5) |
| Settings file | `Windows XP\Unattended\usos-xp.ini` | `Windows 2000\Unattended\usos-xp.ini` (same keys) |
| UEFI summary | | extra note `boot.summary.w2k_limits` (27 locales) |

For 2003 and XP x64 the same seams take one more row each: `Nt5System`
(action, profile), the `usos_nt5_uefi_profile` list, `nt5_profile.sh`
(name, install dir), the pipeline action table and an answer template.
XP x64 additionally needs an amd64-aware probe and local-source copy
(`AMD64\` plus `I386\` boot files).

## 3. Drivers, disk, HAL and CPU

**XP driver bundle on NT 5.0: does not load.** Import resolution of the
bundle (the `check_xp_driver_imports.py` method) against the W2KPLCMA4.811
kernel `ntkrnlmp.exe` and `halmacpi.dll` (5.0.2195, SP4, 2003-06-19):

| Module | Unresolved on 2000 |
|---|---|
| `ntoskrn8.sys` | 11: `ExAcquire/ReleaseRundownProtection(Ex)`, `ExInitializeRundownProtection`, `ExfReleasePushLock`, `InterlockedPushEntrySList`, `KeGetRecommendedSharedDataAlignment`, `PsGetThreadWin32Thread`, HAL `KeAcquire/ReleaseInStackQueuedSpinLock` |
| `storport.sys` | HAL `KeAcquireInStackQueuedSpinLock`, `KeReleaseInStackQueuedSpinLock` |
| `acpi.sys` (community) | `ExfInterlockedCompareExchange64`, `HeadlessDispatch`, `InterlockedPop/PushEntrySList` |
| `wdfldr.sys`, `usbd8.sys` | `RtlGetVersion` |
| `wpprecor.sys` | `RtlGetVersion`, `KeRegister/DeregisterBugCheckReasonCallback` |
| `genahci.sys`, `wdf01000.sys`, `usbxhci.sys`, `usbhub3.sys`, `ucx01000.sys`, `ksecd8.sys` | 0 (but they sit on the modules above) |

**Correction (2026-09-27, [research/win2000-ahci.md](research/win2000-ahci.md)):**
the table counts only direct imports. Most `ntoskrn8.sys` exports are
forwarders to `ntoskrnl`, and following them for StorPort's imports gives
about **24 distinct missing functions** on 2000 (not 11/13). The conclusion
is the same, only stronger. For later, that note recommends AHCINT
(GPL-3.0, Win2000 F6 files, matches the AMD 1022:7901/43C8/43EB controllers)
with UniATA as the fallback; 2000 on the X470 stays parked.

So GenAHCI has no working StorPort on 2000, and KMDF/USB3 have no loader.
The 2000 profile therefore stages **no** bundle (`[W2K_DRIVERS] none` in
the log) and Setup uses its inbox drivers.

- **Storage on the X470:** AMD 400-series SATA offers AHCI or RAID, no IDE
  mode. 2000 has no inbox AHCI driver, so text-mode Setup is expected to find
  no disk (or STOP 0x7B after the restart). Needed: an NT 5.0 AHCI/NVMe
  driver supplied by the user; USOS does not redistribute modified Microsoft
  binaries (for example the "Extended Kernel"). Targets with IDE/legacy SATA
  mode (older boards, QEMU/VirtualBox PIIX) work.
- **48-bit LBA:** the plan caps the Windows partition at 128 GiB
  (`xp_windows_partition_plan.awk`), so 2000's atapi never needs
  `EnableBigLba`. It is not set. Space beyond 128 GiB stays unallocated; the
  CSMWrap ESP at the disk end is a partition 2000 does not mount.
- **HAL / ACPI:** Setup picks the HAL as before (ACPI multiprocessor on
  modern boards). The community ACPI.SYS cannot be used (above), so AM4
  boards keep the risk of STOP 0xA5 from ACPI 5.0 (nt5-uefi-family.md 3.1).
- **CPU / RAM:** 2000 Professional uses 2 logical processors and 4 GB.
- **USB:** no xHCI driver; text mode needs PS/2 or USB legacy emulation
  (CSM). Text mode itself needs no keys (the disk was chosen in USOS).

## 4. Sources: the CMA repacks (quirks)

The user's media are Polish repacks, not MSDN originals; accepted for tests
like NiKKA for XP. Local test assets: git-ignored, never in a release.

| ISO | SHA-256 |
|---|---|
| `W2KPLCMA4.811.iso` (701 MiB, 2008-11-26) | `ae0940f2189c496fc527cb58e7fac102eb97619fca84c866249cf7b3315cde76` |
| `W2KPLCMA6.7.15.iso` (748 MiB, 2010-07-24) | `0b993077f9bdaa287eafea5e152b62fd3bf896e7cc7ccb04ce905b520d68089d` |

Observed (both, unless noted):

- Professional, 5.0 SP4 slipstream: `TXTSETUP.SIF [SetupData]`
  MajorVersion 5, MinorVersion 0, ProductType 0,
  `DriverCabName=driver.cab,sp4.cab`, `OsLoadOptions="/fastdetect /noguiboot /nodebug"`.
- Service pack markers: `CDROMSP2.TST` **and** a lowercase `cdromsp4.tst`;
  `I386\sp4.cab`/`sp4.cat` lowercase next to an old `SP2.CAB`. The probe
  accepts the lowercase SP4 marker; the ISO9660 mount resolves `SP4.CAB`.
- Extra, not used by USOS: `Aktualizacja.cmd` (root), `Software\` (updates,
  .NET 1.1/2.0, DirectX 9c, MSXML), `SP1\vcredist_x86.exe`, `Tool\unmsjvm.exe`;
  `I386\SVCPACK\` with IE6 SP1 / OE / WMP CABs (installed by Setup's
  SVCPACK.INF, copied with the complete I386).
- The staging needed no repack fix: DOSNET aliases 2 (USETUP/NTDLL, as for
  XP), 109 boot-folder rows, 5564 files on the target, no zero-filled file.

## 5. Tests (2026-09-27)

- QEMU TCG, UEFI-CSM stand-in (the package's own scripts prepare a blank
  12 GiB disk, then SeaBIOS boots it), usos-xp.ini with an account:
  `run_seabios_xp_uefi_csm_textmode.py --profile w2k-x86-sp4-uefi-csm`:
  W2KPLCMA4.811 **and** W2KPLCMA6.7.15: PREPARED PASS, text-mode Setup
  "Kopiowanie plików" (copying).
- QEMU TCG, OVMF **without CSM**:
  `run_csmwrap_xp_prepared.py --profile w2k-x86-sp4-uefi-csm --run-through`
  (W2KPLCMA4.811): CSMWrap ESP PASS, firmware -> CSMWrap -> SeaBIOS -> 2000
  text-mode copy -> restart -> second CSMWrap boot -> GUI Setup
  ("Instalator systemu Windows 2000 Professional", "Instalowanie urządzeń",
  about 20 min of TCG; `zig-out/w2k-csmwrap-qemu/csmwrap-boot`). Without a
  product key usos-xp.ini gives `DefaultHide`, so Setup stops at the key page
  (not bypassed).
- XP default unchanged: `target_digest.py` of an XP target prepared by the
  previous package (B260927-163602) and the new one: identical (7010
  files, WINNT.SIF, TXTSETUP.SIF, MIGRATE.INF, MBR/VBR). `compare_xp_packages`
  0 unexplained; check_xp_* PASS; staged-payload goldens: the edited
  scripts plus one added file.
- Host: routing golden (2000 UEFI rows only; BIOS rows unchanged), pipeline
  table tests, `test_xp_user_settings.py` (2000: ProductID, `\WINNT`, no PAE;
  XP output unchanged), Zig command-line test for the 2000 action/profile.
- Not run: VirtualBox BIOS to the desktop (no 2000 product key available;
  the BIOS path is unchanged). No X470 test (needs an AHCI driver, section 3).
