# Windows NT 3.1 Workstation / Advanced Server without CSM (2026-10-09)

NT 3.1 uses the NT 3.x VM flow (docs/nt351-2026-10-08.md, profile
`nt3-x86-qemu-csmwrap`, experimental, UEFI only): UEFI menu, micro-Linux
step 620, the whole install in QEMU on the target PC, automatic restart,
then the target disk's CSMWrap entry starts the finished system. The same
NT 3.x MBR (E820 filter, HPET legacy off, PCI BIOS hidden past bus 7).
Setup itself is a different generation, so most of the work is new.

## What the user needs on USOS_DATA

| What | Where |
|---|---|
| NT 3.1 Workstation CD | `Systems\Windows\Windows NT 3.1\Images\*.iso` |
| NT 3.1 Advanced Server CD | `Systems\Windows\Windows NT 3.1 Advanced Server\Images\*.iso` |

Menu entries `windows-nt-3-1` and `windows-nt-3-1-server` (answer files
`NT31.SIF` / `NT31S.SIF`: only `[UserData]` is used, see below). No product
key, no service pack.

## How the install runs

NT 3.1 Setup has `I386\TXTSETUP.INF` (no TXTSETUP.SIF, no MajorVersion) and
`I386\SETUPLDR` (no .BIN). Its text-mode Setup is `SETUPAPP.EXE`, a program
inside the loader: it reads files through BIOS disk calls, so from a local
source on C: it needs no CD driver (the CD path would need ISA/EISA SCSI).

1. `tools/nt4_csmwrap_target.sh` (`nt31_layout`): what the NT 3.1
   `winnt.exe` does, without the floppy. `I386` flat to `\$WIN_NT$.~LS`
   (DOSNET.INF `d1 = \`), the DOSNET `[FloppyFiles]` (the boot floppy:
   NTDETECT.COM, the DISK1 tag, the SCSI miniports, SETUPAPP.EXE) on the
   root of C:, `TXTSETUP.INF` with a `[MsDosInitiated]` section appended
   (winnt.exe does the same on the floppy), SETUPLDR as `$LDR$` behind
   syslinux `chain.c32 ntldr=`. C: is 500 MiB FAT16 with 8 KiB clusters and
   one reserved sector (`NT31_PART_SECTORS`, `NT31_CLUSTER_SECTORS`): the
   NT 3.1 fastfat stopped with 0x1E at the first GUI start on the 2000 MiB /
   32 KiB / 32-reserved-sector volume the other NT flows use.
   `\USOS\NT3`: the NT 3.1 driver builds, `SOURCE.TXT` (version=3.10),
   `NAMES.TXT` (owner, organisation, computer from WINNT.SIF
   `[UserData]`), `POST.CMD`, `ROOTLIST.TXT` (root files removed after the
   install).
2. `tools/nt4_qemu_install.sh`, VM run 1 (Pentium, IDE, 64 MiB): text mode
   has no answer file; `nt31_vm_tick` (a `W9X_VM_TICK_FN` hook in
   `w9x_phase1_run`) reads the VGA text page (QEMU `pmemsave` of B8000h)
   every 4 s and presses ENTER on Welcome, Express Setup, the partition C:,
   "keep the FAT file system" and `\winnt`, then CTRL+ALT+DELETE (the
   restart ends the VM). About 75 s under TCG.
3. Between the runs `nt31_vm_patch_initial` edits the plain-text
   `C:\WINNT\SYSTEM32\INITIAL.INF` and `HARDWARE.INF` that text mode wrote
   (mtools, nothing from the CD is shipped): no network, printer or
   application search; owner / organisation / computer name set; blank
   Administrator password, no extra user; no Emergency Repair Disk; the Language (Locale) page keeps the default; at
   the end `[UsosNt31Post]` writes the Services keys (ahcint and usosrst
   boot start, group "SCSI miniport" - NT 3.1 has no "System Bus Extender"
   group; usosusb also boot start: as a system driver its DriverEntry never
   ran on 3.1; Scsidisk Start 0; Atdisk off; Kbdclass/Mouclass
   ConnectMultiplePorts; Winlogon DefaultUserName = Administrator), runs
   `POST.CMD` (copies the drivers, writes DONE.TXT) and restarts without the
   "Setup is done" page.
4. VM run 2: GUI Setup copies the rest, opens the Date/Time applet (kept:
   without the time zone it writes, WinLogon refused Administrator with
   "Your account has time restrictions"), which the runner accepts with
   ENTER after the usual idle time (`NT31_VM_ANSWER`, 180 s without disk
   writes), and ends;
   Advanced Server (2026-10-10, see below) installs its network here first
   and stops at Domain Settings, the runner's first answer;
   `nt4_vm_finish` writes BOOT.INI `/NODEBUG /MAXMEM=64` (without /NODEBUG
   the 3.1 kernel runs its debugger on COM1), removes the floppy files and
   the local source.

## QEMU 2026-10-09

Workstation and Advanced Server: install to DONE.TXT (2 VM starts; the
host harness mirrors the runner: text pages by screen text, ENTER on the

## Advanced Server: domain controller on the MS Loopback Adapter (2026-10-10)

The first AS install booted to its logon screen and refused Administrator:
"Unable to log you on because the netlogon service is not running". 3.1 AS
is always a domain controller; with the network page switched off its Setup
never created the domain (role STANDALONE, no Lanman services, no
netlogon), and MSV1_0 on a LanmanNT system hands every logon to netlogon.

Fix (cheapest that runs without any network card, as on the X470): AS Setup
keeps the network and installs the **MS Loopback Adapter** from its own CD
(OEMNADLB.INF, LOOP.SYS; software only) with the NetBEUI, Server,
Workstation, NetBIOS and RPC locator defaults of NTLANMAN.INF. Between VM
runs `nt31_vm_patch_initial` sees `STF_PRODUCT = LanmanNT` in INITIAL.INF
and then:

- leaves `DoNetwork = $(Chosen)` (printer and application search still
  off);
- NTLANMAN.INF `[InitialAdapterInstall]`: during Setup (`NTN_Origination
  install`) `STF_NCOPTION = LOOP` and straight to `detectbypass` - no
  detection, no adapter list (`nt31_ntlanman_inf`);
- OEMNADLB.INF: during Setup no media type page, 802.3 stays
  (`nt31_oemnadlb_inf`).

Later Control Panel Network runs (`NTN_Origination ncpa`) behave as on the
CD. The one page left is NCPA's Domain Settings (3.1 has no unattended form
of it): the runner's answers are now per attempt (`W9X_VM_ANSWER` "keys;keys",
`w9x_phase1_qemu.sh`), for AS `alt-c tab U S O S D O M A I N ret;ret`
(`NT31_AS_VM_ANSWER`, domain name keys `NT31_DOMAIN_KEYS`): controller in
the new domain USOSDOMAIN, then ENTER for the Date/Time applet. Logon: user
Administrator, blank password, "From" the domain.

QEMU 2026-10-10: GUI Setup reached Domain Settings 62 s in (no other page),
then Date/Time; installed system under OVMF + CSMWrap **without any NIC**
(`-nic none`): logon Administrator from domain USOS (typed by hand in that
run) -> Program Manager "USOS\Administrator". Then a fresh automated
install (host harness with the runner's rules: answers after 90 s without
disk writes, the AS answer list): Domain Settings filled and accepted at
122 s, Date/Time at 224 s, DONE.TXT, finish PASS; OVMF + CSMWrap without a
NIC: logon -> Program Manager "USOSDOMAIN\Administrator".

## Memory: AH=88h / AX=E801h from the MBR (2026-10-10)

The NT 3.1 NTLDR / SETUPLDR (startup code, 16-bit) know no E820: base
memory from INT 12h, the block at 1 MiB from INT 15h AH=88h, and a block
at 16 MiB from AX=E801h BX - only when E801h AX equals the AH=88h value.
SeaBIOS in CSMWrap answers both from LegacyRamSize, the end of the first
contiguous RAM above 1 MiB: OVMF's reserved range near 8 MiB stops it there
(WINMSD: 8,128 KB), and above 64 MiB AH=88h says 63 MiB while E801h AX says
15 MiB, so E801h is ignored.

`src/platform/bios/nt3/nt3_e820_mbr.S` (all NT 3.x entries) now answers
AH=88h and AX=E801h itself: AX (and CX) = the BIOS E801h AX (contiguous RAM
1-16 MiB, as before), BX (and DX) = 64 KiB blocks of the E820 RAM entry
that covers 16 MiB, up to its end (at most 4 GiB). E820 answers are
unchanged. The resident hooks no longer fit into the 440-byte MBR: they
moved to sector 1 of the disk (`nt3-e820-hook-512.bin`, "U3" in its last
two bytes, written by `nt4_csmwrap_target.sh`; the partition starts at 63).
The MBR reads it into the reserved 1 KiB and boots without hooks when the
sector is missing. BOOT.INI keeps `/MAXMEM=64`.

QEMU 2026-10-10 (WINMSD Memory, AS disk, 2 GiB guest): OVMF + CSMWrap
8,128 KB -> **57,152 KB** (1-8 MiB + 16-64 MiB; the OVMF hole stays
unused); SeaBIOS without CSMWrap 65,088 KB (contiguous RAM, the case
expected on the X470). Fresh Workstation install with the new MBR (sector 1
written by the target script, install VM on SeaBIOS through the hooks):
OVMF + CSMWrap, USB keyboard logon -> Program Manager, WINMSD 57,152 KB.

## Open problems

- The micro-Linux runner's text-page tick and INF patch ran in the nested
  harness pieces only (patch in micro-Linux, pages and answers in the host
  harness); the first full run is the X470 one. The Domain Settings answer
  is typed blind after 180 s without disk writes: if the X470 run stops
  there, type the domain name, choose "Controller in New Domain" and OK.
- NT 3.5 / 3.51 also boot through the new MBR (sector-1 hooks); they use
  E820, their AH=88h / E801h answers changed only in consistency. Not
  rebooted in QEMU after this change.
- autochk at boot says "The type of the file system is RAW" for C: and
  goes on (VM and CSMWrap alike).
- VGA only (640x480x16), no Polish characters (English CDs).
