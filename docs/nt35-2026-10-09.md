# Windows NT 3.5 Workstation / Server without CSM (2026-10-09)

NT 3.5 uses the NT 3.51 flow (docs/nt351-2026-10-08.md, profile
`nt3-x86-qemu-csmwrap`, experimental, UEFI only): UEFI menu, micro-Linux
step 620, the whole install in QEMU on the target PC, automatic restart,
then the target disk's CSMWrap entry starts the finished system. The same
NT 3.x MBR (E820 filter, HPET legacy off, PCI BIOS hidden past bus 7), the
same AHCINT NT 3.51 build (usos6) and usosusb, the same USOSNT3 service.

## What the user needs on USOS_DATA

| What | Where |
|---|---|
| NT 3.5 Workstation CD | `Systems\Windows\Windows NT 3.5\Images\*.iso` |
| NT 3.5 Server CD | `Systems\Windows\Windows NT 3.5 Server\Images\*.iso` |

No product key (INITIAL.INF `DisplayPidDlg = NO`, as on 3.51), no service
pack. The menu entries are `windows-nt-3-5` and `windows-nt-3-5-server`
(answer files `NT35.SIF` / `NT35S.SIF`, the NT 3.51 WINNT.SIF: the 3.5
INITIAL.INF reads the same `!`-prefixed keys, `!DetachedProgram` included).

## Differences from NT 3.51

- **CD check**: `nt4_csmwrap_target.sh` accepts `[SetupData] MinorVersion`
  50 and 51; `NT_MINOR` (from the menu entry) must match the CD.
- **HAL row**: the 3.5 TXTSETUP.SIF names its MPS HAL `mps11_mp`
  (halmps.dll); `nt3_standard_hal` rewrites every `mps*_up/mp` row to the
  Standard PC `hal.dll`.
- **Install VM CPU**: NT 3.5 GUI Setup (INITIAL.INF `GetProcessor`) knows
  no CPU newer than a Pentium, so the VM runs `-cpu pentium`
  (`NT35_VM_CPU`); nt4_qemu_install.sh reads `version=3.50` from
  `\USOS\NT3\SOURCE.TXT`.
- **Install VM disk**: the 3.5 CD has no amsint.sys; its atdisk.sys runs
  text mode on QEMU IDE without the NT 3.51 interrupt nesting, so the VM
  uses IDE (`NT35_VM_HBA`, empty by default).
- **usosrst**: the 3.5 kernel exports neither `KeSetTargetProcessorDpc`
  nor `KeSetImportanceDpc`; `build-nt35.cmd` (`-DUSOSRST_NT35`) keeps one
  heartbeat CPU DPC, version string `usosrst 1.6-nt35`. micro-Linux ships it
  as `/usr/lib/usos/nt3/USOSRST35.SYS`; the target script copies it as
  `\USOS\NT3\USOSRST.SYS` for a 3.5 CD. AHCINT (NT351 build) and usosusb
  resolve on 3.5 as they are (`tools/tests/data/nt35_exports.txt`, names
  only, checked by `test_nt3_flow.py`).
- **Disk class driver**: Setup on the VM's IDE disk leaves `Scsidisk` at
  Start 1, so the first CSMWrap boot through AHCINT stopped with 0x7B
  (AHCINT read the disk, no class driver at boot). USOSNT3 now sets
  `Scsidisk` Start 0 (3.51 has it already: its VM disk is SCSI).
- **Memory cap**: with more than 128 MiB the 3.5 kernel stops with 0x7B
  (C0000034, the ARC name of the boot disk is missing) after one AHCINT
  read; 64 and 128 MiB boot, 256 MiB and 2 GiB stop (QEMU OVMF + CSMWrap,
  EPYC-Rome). BOOT.INI gets `/NUMPROC=2 /MAXMEM=128` for a 3.5 system
  (`NT35_BOOT_OPTIONS`, nt4_vm_finish reads `version=3.50`); 2 GiB with
  `/MAXMEM=128` boots. The exact cause (somewhere between 128 and 256 MiB)
  is not known yet.
- Text-mode Setup reads AUTOCHK.EXE from `~BT` (DOSNET `[FloppyFiles.2]`)
  and says "Setup was unable to verify your C: drive"; the VM runner's
  ENTER answer (as for 3.51) goes on.

## QEMU 2026-10-09 (NT 3.5 Workstation EN, build 807)

Hands-free install (VM: -cpu pentium, IDE, 512 MiB): text mode, GUI
Setup and the USOSNT3 service, DONE.TXT after the third VM start; finish
PASS (BOOT.INI, autochk restored, dirty bit cleared, CSMWrap ESP). Then
q35, OVMF + CSMWrap, EPYC-Rome (Zen 2 like the X470's 5700X), 2 CPUs,
2 GiB, ich9-ahci (AHCINT usos6), qemu-xhci keyboard + mouse, 12
pcie-root-ports (PCI BIOS hidden by the MBR): logon screen
"Windows NT Workstation Version 3.5" (build 807). NT 3.5 Server: no CD in
the library, untested (the CD decides the Server answers, as on 3.51).

## NT 3.1 / 3.1 Advanced Server

No longer parked: docs/nt31-2026-10-09.md (installed from the local source
on C:, text mode answered by screen text, GUI Setup from a patched
INITIAL.INF, NT 3.1 driver builds). The notes below are the original reasons.


Different Setup generation: TXTSETUP.INF (no TXTSETUP.SIF, no
MajorVersion), SETUPLDR without `.BIN`, the text-mode kernel and drivers
read from the CD (`d2 = ...\i386`) through ISA/EISA SCSI miniports only (no
ATAPI, no PCI SCSI in QEMU terms), no `[Unattended]` text mode and no
`!DetachedProgram` / unattended keys in INITIAL.INF (only
`GetProcessor`). Our drivers would need NT 3.1 builds (AHCINT and usosrst
import `KeRegisterBugCheckCallback` and `memset`; usosusb
`IofCompleteRequest`, `KfRaiseIrql`, `KfLowerIrql`). A 3.1 path would mean
generated boot floppies, key scripting through text and GUI Setup and new
driver builds.

Tests: `tools/tests/test_nt3_flow.py`, `src/flow/answer/nt3.zig`,
`src/catalog/os_profiles.zig`, `src/flow/testdata/routing_golden.tsv`.
