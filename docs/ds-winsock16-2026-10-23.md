# WINSOCK.DLL dla Win16 - rozpoznanie Trumpeta i szkielet USOS (2026-10-23)

Galaz: `ds/winsock16`, baza `074dfe0d`.  Plan nadrzedny:
`docs/win3-winsock-options-2026-10-23.md` (M2 = wlasna, GPL, `WINSOCK.DLL`
Win16 oparta o mTCP + USOSPKT).  Trumpet Winsock 3.0 sluzy wylacznie jako
wzorzec ABI: nie skopiowano z niego zadnego kodu ani zadnego pliku.

### 1.1 Kompresja: gzip, nie SZDD/KWAJ/LZP

Pierwsze 16 bajtow kazdego `*.*_` to `1f 8b 08 00 00 00 00 00 02 00 ...`, czyli
strumien **gzip** (deflate), a nie formaty SZDD (`SZDD`), KWAJ (`KWAJ`) ani LZP
Tattama.  Dekompresja zwyklym gunzipem (GZipStream) dala poprawne moduly `MZ`:

```
WINSOCK.DL_ -> WINSOCK.DLL  168192 B  MZ, e_lfanew=0x100
TWSK16.DL_  -> TWSK16.DLL     6336 B  MZ, e_lfanew=0x80
WSOCK32.DL_ -> WSOCK32.DLL   39936 B  MZ, e_lfanew=0x80
```

Naglowek NE `WINSOCK.DLL`: `NE`, link 6.1, entry table 0x103 (0x0B04 B),
9 segmentow, exetyp = Windows, oczekiwana wersja Windows 0x0300, tablica
nazw rezydentnych pod NE+0xA0 (`WINSOCK` @0, `WEP` @0x0400), tablica nazw
nierezydentnych pod offsetem 0x0D07 - tam sa nazwy eksportow.

### 1.2 Realna tablica ABI Trumpeta

Z tablicy nazw nierezydentnych odczytano 72 eksporty (pliki: `WINSOCK.DLL`).
Ordinalе pokrywaja sie dokladnie z publiczna specyfikacja Winsock 1.1
(zalacznik "Name and ordinal"): `accept`=1 ... `socket`=23, baza danych
51..57, rozszerzenia WSA 101..116, `__WSAFDIsSet`=151.  **`WSAStartup` to
ordinal 115, nie 1.**  Pelna tabela: `docs/win16-winsock-abi.tsv`.

Dodatkowo Trumpet eksportuje wlasne, nieznormalizowane funkcje (ordinalе
1000-1023): `TCPCONTROL`, `TCPINFOPTR`, `TCPSOCKETINFO`, `TCPGETPKTVEC`,
`TCPSETPKTVEC`, `TCPSETIPADDR`, `TCPGETVERSION`, `TCPSETSLIPINFO`,
`GET_COMM`, `PUT_COMM`, `TCP_METER`, `SOCKS_SETUP`, `ROUTE_ADD/DEL/GET`,
`TCPSETPPPOPTIONS`, `TCPSETBUFFERS`, `TCPSETDRIVERADDRESS`,
`TCPGETDRIVERADDRESS`, `TCPSETSLIPBUF`, `TCPSETFILTERPROC`, `TCPSENDPKT`,
`TCPGETERRORMESSAGE`, `TCPPPPDONE`.  To ich prywatne ABI (np. dla `TCPMAN`),
swiadomie **nie** jest czescia naszej tablicy eksportow.

`TWSK16.DLL` eksportuje te same nazwy Winsock (podzbiór, m.in. `SEND` @19,
`WSASTARTUP` @115) plus `DLLENTRYPOINT` @2001, `THK_THUNKDATA16` @2000 -
to warstwa thunkow, nie API dla aplikacji.### 1.3 Licencja - najwazniejszy wynik rozpoznania

### 1.4 Fakty z `README.TXT` / `README.1ST`

* Wersja: "Trumpet Winsock Version 3.0 Rev D by Peter R. Tattam",
  "for Win3.1x / Win95", data 16/10/96.
* Dwa tryby transmisji: dial-up (SLIP/CSLIP/PPP) oraz siec lokalna przez
  **packet driver** (ODI/NDIS/packet driver shim).
* Dla sieci: "[ ] Installing a packet driver and WINPKT" oraz w
troubleshootingu "Is winpkt or ndis3pkt being used?" - czyli **WINPKT jest
wymagany** dla packet drivera pod Windows.
* `README.1ST` odsyla po warunki dystrybucji do menu `Help/Distribution`
  w programie (nie ma ich w plikach tekstowych).
* `TRUMPWSK.INI`: w `README.TXT` wystepuje tylko przy aktualizacji -
  "Copy the trumpwsk.ini file from a previous registered Trumpet Winsock";
  nazwy kluczy nie sa tam opisane (sa w `TRUMPWSK.HLP`).
* Tryby real/standard/enhanced: **brak wzmianki** w `README.TXT` i
  `README.1ST`; DHCP/BOOTP: **brak wzmianki**.  Nie badano `TRUMPWSK.HLP`
  (binarny WinHelp), wiec tych faktow nie potwierdzamy.

## 2. Co zbudowano (milestone 1)

| Plik | Rola |
| --- | --- |
| `src/platform/bios/win16/winsock16/winsock16.c` | 47 funkcji Winsock 1.1, `LibMain`, `WEP` |
| `src/platform/bios/win16/winsock16/winsock16.def` | eksporty + ordinalе ze specyfikacji |
| `tools/build_win16_winsock.py` | build Open Watcom (wcc + wlink) |
| `tools/tests/test_win16_winsock.py` | testy .def / NE / brak plikow Trumpeta |
| `docs/win16-winsock-abi.tsv` | tabela ABI (fakt publiczny + zgodnosc z NE Trumpeta) |

`WSAStartup` jest funkcjonalny: negocjuje wersje (`wVersion` = 0x0100 dla
zadania 1.0, 0x0101 dla 1.1), ustawia `wHighVersion=0x0101`,
`szDescription="USOS Winsock 1.1 (Win16)"`, `szSystemStatus`,
`iMaxSockets=8`, `iMaxUdpDg=512`, `lpVendorInfo=NULL`; przy `lpWSAData==NULL`
zwraca `SOCKET_ERROR` z `WSAEFAULT`, przy major != 1 - `WSAVERNOTSUPPORTED`.
`WSACleanup`, `WSAGetLastError`, `WSASetLastError` dzialaja.  Pozostale
entry pointy to stuby: `SOCKET_ERROR` + `WSAENETDOWN`, a `WSAAsyncGet*`
zwracaja `NULL` + `WSAVERNOTSUPPORTED`.  W pliku jest znacznik
"milestone 2: silnik TCP/UDP na mTCP + USOSPKT w trybie kolejkowym".### 2.1 Stan builda: kompilacja OK, link zablokowany przez toolchain

`wcc` (Open Watcom `ow-bac354f3c75f`, `binnt64`) kompiluje plik bez bledow:

```
wcc -bt=windows -bd -ml -zW -zq -w3 -I<ow>\h\win -fo=...\winsock16.obj winsock16.c
```

Dwie realne poprawki ABI wyszly dopiero na kompilatorze, bo `winsock.h` jest
autorytatywny: `WSANOTINITIALISED` (nie `WSAENOTINITIALISED`) oraz
`WSAAsyncGetHostByAddr(HWND, u_int, const char FAR*, int len, int type,
char FAR*, int)` - 7 parametrow, w tym `type`; bez niego kompilator zglaszal
E1071/E1151.

**Link nie przechodzi** z tym `wlink.exe` (Open Watcom Linker 2.0 beta,
build 2026-09-01, 64-bit "EXPERIMENTAL").  Zaobserwowane bledy:

* `system windows_dll` -> `W1107: undefined system name: windows_dll`
  (mimo `WATCOM` ustawionego; bez niego `W1115: environment name WATCOM not found`).
  Blok `system begin windows_dll` istnieje w `binnt64\wlink.lnk`, ale linker go
  nie laduje.
* `.def` podany jako plik -> `E3146: ... is an invalid object file`
  (a jako goly argument -> `E3033: directive error near '<...>.def'`).
* `option definition=<def>` -> `E3033: directive error near 'definition'`.
* `option export=WSAStartup=115` -> `E3033: directive error near 'export'`.

Czyli ten build linkera nie obsluguje plikow definicji modulu.  Skutek:
`zig-out/win16/WINSOCK.DLL` **nie powstalo**, a test NE konczy sie `skip`
zgodnie z zalozeniem.  `tools/build_win16_winsock.py` dziala poprawnie w obu
pozostalych przypadkach: brak OW -> czytelny komunikat i `exit 0` (`--strict`
zmienia to w blad), blad kompilacji/linku -> `exit 1` z komenda w `--verbose`.

Do rozwiazania w kroku 2 (w kolejnosci prob): (a) stabilny `wlink` z innego
cache/instalacji OW; (b) jesli def jest nieobslugiwany - `wlink` z plikiem
dyrektyw `@winsock16.lnk` generowanym z `.def` albo eksporty przez
`__declspec(dllexport)` plus reczne ordinalе; (c) `format windows dll` +
`libfile libentry.obj` jako obejscie bloku systemowego.

## 3. Nastepny krok (M2 krok 2)

1. Silnik TCP/UDP/DNS na kodzie mTCP (GPL-3.0) pod Win16: warstwa `select`
   oparta o WSAAsyncSelect + pompe komunikatow, bufor per socket.
2. USOSPKT w trybie kolejkowym jako transport pod mTCP (bez WINPKT - wlasny
   packet driver juz jest w `src/platform/bios/msdos/usospkt.S`).
3. Uruchomienie w QEMU z Windows 3.1: `WSAStartup`, `socket/connect/send/recv`,
   `gethostbyname`, test z `ping`-em po TCP; pomiar `iMaxSockets`.
4. Domkniecie linkera (2.1) i wtedy wlaczenie testu NE jako twardego wymagania.

## 4. Czego nie sprawdzono

* Dzialania `WSAStartup` na zywej instalacji Windows 3.1/QEMU (brak artefaktu).
* Zawartosci `TRUMPWSK.HLP` - tryby real/standard/enhanced, DHCP i klucze
  `TRUMPWSK.INI` pozostaja niepotwierdzone; `README.TXT` ich nie opisuje.
* `WSOCK32.DLL` (wariant Win32) - tylko rozpakowany i sprawdzony naglowek.
* Zgodnosci ordinalow z dokumentacja Microsoftu - potwierdzone dwustronnie:
  tablica NE Trumpeta + zalacznik specyfikacji Winsock 1.1 (oba zgodne).
* `build.bat` nie byl uruchamiany (opcjonalny).
