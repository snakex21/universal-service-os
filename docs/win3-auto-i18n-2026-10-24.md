# Windows 3.0a Setup without clicks; DOS texts in the USOS languages (2026-10-24)

## A. Windows 3.0a: graphical Setup answered by what is on screen

User report (X470): after MS-DOS, the graphical part of Windows 3.0a Setup
needed clicks; the DOS part was automatic.

Cause: Windows 3.0 has no batch Setup (no `SETUP /H`); USOS answers its
graphical part with USOSKBC key scripts (keys through the 8042 into
KEYBOARD.DRV). `W30.KEY` sent them after fixed delays: 25 s after the first
graphics mode (options dialog), +90 s (CONFIG.SYS dialog, after the file
copy), +20 s (saved-files note), +20 s (`Alt+D` = Return to DOS). The copy
and Windows start take a different time on the X470 than in QEMU: a key
that comes before its dialog is lost, a dialog that comes early waits up to
90 s for its key (a person clicks), and every later key then lands on the
wrong dialog. The exit dialog's focused button is "Restart Windows": an
Enter there leaves Windows running Setup's session, so WINMENU.BAT (the
start menu) only runs after the person exits Windows.

Fix (own code): USOSKBC script op 6 `pix` waits for a picture in VGA mode
12h: the plane-0 bytes of a black-and-white rectangle hashed
(`h = rol(h, 5) xor byte`), checked every 4 timer ticks from the INT 08h
handler; the graphics controller index, read map select and mode registers
are restored, all 32-bit registers kept. Each step has a timeout after
which the script goes on (the old behaviour), so a picture that never
matches cannot stop the install. `W30.KEY` now waits for each dialog:

| Dialog | Rectangle (byte col, line, bytes x lines) | Answer |
|---|---|---|
| "After Setup installs Windows 3.0 ... checked procedures" | Instructions box 3, 398, 60 x 12 | Alt+P Alt+A Alt+D Enter (no printers, no app search, no documents) |
| "Setup needs to modify your CONFIG.SYS and AUTOEXEC.BAT" | 3, 398, 60 x 12 | Enter (make all modifications) |
| "The new versions ... have been saved" | note text 24, 196, 34 x 14 | Enter (OK) |
| "Exit Windows Setup" | 3, 398, 60 x 12 | Alt+D (Return to DOS -> WINMENU.BAT) |

Hashes from QEMU screendumps (`python tools/usos_keyscript.py --hash
boot.png X Y W H`). The rectangles avoid the mouse pointer (screen centre).
Tests: `tools/tests/legacy_bios/test_usoskbc_pix.py` (Unicorn).

QEMU only (X470-like path: OVMF -> CSMWrap -> SeaBIOS, NVMe behind a root
port, qemu-xhci keyboard + mouse, no key sent by the harness):
`run_w9x_micro_linux_qemu.py w3 --env E2E_WIN_EARLY=windows-3-0 ...`
reached Program Manager after the start-menu restart, also with the boot
disk throttled (`--boot-iops 60`); the dialogs were answered as soon as
they were drawn. Not yet tried on the X470.

## B. DOS-side texts follow the language

Before: Polish-only CONFIG.SYS menus and W3AUTO / NETSTART messages, English
INSTALL / WINMENU messages. Now the sources are English and 52 `dos.*` keys
in `installer/internal/i18n/locales/*.json` (the 27 USOS catalogs; machine
translations) carry the texts. `tools/build_dos_i18n.py` writes
`EFI/USOS/dos-native/i18n/DOSTEXT.TXT`, one section per language and DOS
code page:

- 437 for what is shown before `MODE CON CODEPAGE SELECT`: the CONFIG.SYS
  menus (IO.SYS draws them with the VGA font), INSTALL.BAT, WINMENU.BAT,
  W3START / W1SETUP, NETSTART.BAT (the MS-DOS AUTOEXEC calls it before the
  regional lines). Letters 437 lacks lose their accents ("domyslny");
  Russian, Bulgarian, Greek and Ukrainian have no 437 section: English.
- The MS-DOS 6.22 country code page (852 cs/hr/hu/pl/ro/sk/sl/sr-Latn, 850
  da/de/es/fi/fr/it/nb/nl/pt-BR/sv, 866 ru, 855 bg, 869 el, 857 tr) for
  W3AUTO / W1AUTO, whose lines run after the code page switch, when the
  profile's DOS.INI switches to it. Ukrainian, Estonian, Latvian and
  Lithuanian have no MS-DOS 6.22 country: 437 (English for Ukrainian).

Language: DOS.INI `language=` (src/flow/answer/dos.zig writes the
profile's language), else `[ui] language=` of usos-settings.ini (the USOS
menu), else English. `dos_csmwrap_target.sh` -> `dos_i18n_apply`
(tools/dos_win3_menu.sh) after the regional lines and before the product
names; awk never inspects a translated line (BusyBox awk would count code
page bytes as UTF-8). Tests: `tools/tests/test_dos_i18n.py`.
