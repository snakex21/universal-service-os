# Windows Server 2003 x86 and Windows XP x64 (NT 5.2) on the USOS paths (2026-09-27)

Status: **experimental**, QEMU only. Built on the per-system table of
[windows-2000-uefi-2026-09-27.md](windows-2000-uefi-2026-09-27.md) and the
NT5 design [design/nt5-uefi-family.md](design/nt5-uefi-family.md).

## 1. Paths and profiles

| System (catalog id, DATA folder) | BIOS | UEFI + CSM / no CSM (CSMWrap) | Action |
|---|---|---|---|
| Windows Server 2003 x86 (`windows-server-2003`, `Windows Server 2003`, last entry of the Server section) | `nt5-staging` | `w2k3-x86-sp2-uefi-csm` | `windows2003-staging` |
| Windows XP x64 (`windows-xp-x64`, `Windows XP x64`, after Windows XP) | `nt5-staging` | `xp-x64-sp2-uefi-csm` | `xp64-staging` |

The UEFI profiles share the XP package (`EFI\USOS-XP`), `lang.cpio` and
`usos.xp_boot=csmwrap`; other UEFI selections are refused
(`w2k3-uefi-other`, `xp-x64-uefi-other`). The BIOS Core sends the new actions
(`linux_boot_params.zig`), the pipeline maps them (`tools/pipeline/run.sh`).
Rows added once, everything else shared:

| Seam | Server 2003 x86 | XP x64 |
|---|---|---|
| `Nt5System` (xp_preparation.zig) | action, profile, arch x86 | action, profile, arch **amd64** (answer profile) |
| `nt5_profile.sh` | `NT5_SOURCE_DIR=I386`, `\WINDOWS`, `USOS\W2K3` | `NT5_SOURCE_DIR=AMD64`, `\WINDOWS`, `USOS\XP64` |
| Source probe (`probe_nt5_source.sh`) | WIN51 + WIN51I?, SetupData 5.2 / i386 / ProductType 1-3 | WIN51 + WIN51AP, SetupData 5.2 / amd64 / ProductType 0, `I386` loader |
| Answer template | `w2k3_selected_partition_uefi_csm.sif` | `xp64_selected_partition_uefi_csm.sif` |
| usos-xp.ini family default | `2003`: `ProductKey`, `[LicenseFilePrintData] AutoMode=PerServer, AutoUsers=5` | `xp`: `ProductKey` |
| Summary note | `boot.summary.nt52_limits` (27 locales) | same |

## 2. AMD64 staging

XP x64's Setup source is `AMD64\` (DOSNET `[Directories] d1=\amd64,
d2=\I386`); `I386\` holds SETUPLDR, NTLDR, NTDETECT and the WOW64 files.
`prepare_xp_local_source.sh` now takes the source directory from the NT5
profile: DOSNET.INF and TXTSETUP.SIF from it, `$WIN_NT$.~LS\AMD64` plus the
complete `$WIN_NT$.~LS\I386`, FloppyFiles `d1` from AMD64 and `d2` from I386
into `$WIN_NT$.~BT`, root NTLDR/`$LDR$` = `I386\SETUPLDR.BIN`, root
TXTSETUP.SIF from AMD64. The DOSNET aliases (`xp_dosnet_aliases.awk`,
`src_dir`) are relative to the source directory. With `I386` every step is
the one before (XP target digest identical, section 5).

## 3. Storage (X470 AHCI) and the driver import check

Import resolution (the `check_xp_driver_imports.py` method, with PE32+
support) against the media's own kernel, HAL and StorPort:

| Driver | Server 2003 R2 SP2 x86 (`ntkrnlmp.exe`, `halmacpi.dll`, `storport.sys` 5.2.3790.3959) | XP x64 SP2 (`ntkrnlmp.exe`, `hal.dll`, `storport.sys`) |
|---|---|---|
| GenAHCI 6.3.0.1 x86 / x64 | **0 missing** | **0 missing** (x64 build) |
| StorPort (the system's own) | 0 missing | 0 missing |
| community ACPI (XP bundle) | 0 missing | - (x86 only) |
| AMD SATA 1.2.001.0337, Kai-Schtrom storahci (x86) | 0 missing | - |

So NT 5.2 needs neither `ntoskrn8` nor the XP StorPort backport.
`tools/nt5_storage_stage.sh` integrates GenAHCI like an F6 driver:
`genahci.sys` in `$WIN_NT$.~BT` and the local source, and four TXTSETUP.SIF
rows (first `[SourceDisksFiles]` block, `[HardwareIdsDatabase]
PCI\CC_010601`, `[SCSI.Load]`, `[SCSI]`). The binaries are in the XP package
(`usr/lib/usos/nt5-storage/{x86,amd64}/genahci.sys`, `gpl.txt`,
`SOURCE.txt`), taken from the pinned `tools/vendor/xp-modern/2026-09-21/
GenAHCI_6.3.0.1.7z` (sha256 f8dd5412...). A preflight refuses the start
before any disk write when they are missing. Only text mode is integrated
(no PnP INF in the GUI phase); NVMe has no driver. USB on xHCI: xhci98 on
branch `feature/nt52-xhci98` ([nt52-xhci98-2026-09-29.md](nt52-xhci98-2026-09-29.md)).

## 4. Server specifics

- **PAE:** no `pae.exe` patching. `usos-setup.cmd` (UserExecute at setup
  end) runs `bootcfg /raw "/PAE" /A /ID 1`; Enterprise then uses more than
  4 GB. SP2 also enables PAE by itself when DEP is on (`/noexecute=optout`).
  Log: `%SystemRoot%\usos-setup.log`.
- **Manage Your Server:** the same script sets the policy
  `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\CurrentVersion\MYS
  DisableShowAtLogon=1`. "Post-Setup Security Updates" is not suppressed.
- **Licensing / password:** from usos-xp.ini or an answer profile
  (`family=2003`): `[LicenseFilePrintData]`, `AdminPassword`. Without a key
  the answer is `DefaultHide` and Setup stops at the key page (not bypassed).
- CD2 (R2 components) is not needed for Setup.

## 5. Tests (2026-09-27, QEMU TCG)

- UEFI-CSM stand-in (the package scripts prepare a blank 12 GiB disk, then
  SeaBIOS boots it) with the target on an **AHCI controller** (`--ahci`,
  PCI class 010601; neither system has an inbox AHCI driver):
  Server 2003 R2 SP2 Enterprise (PL): "Instalator kopiuje pliki..."; XP x64
  SP2 (EN): "Setup is copying files...". GenAHCI therefore loads in text mode.
- OVMF **without CSM** (`run_csmwrap_xp_prepared.py --run-through`):
  CSMWrap ESP PASS, text-mode copy, restart, second CSMWrap boot, GUI Setup
  for both: Server 2003 at "Klucz produktu" (usos-xp.ini without a key:
  DefaultHide stops there, not bypassed), XP x64 at "Welcome to the Windows
  Setup Wizard" (no settings file: interactive). About 20 min TCG each
  (`zig-out/w2k3-csmwrap-qemu`, `zig-out/xp64-csmwrap-qemu`).
- Host: probe fixtures, `test_nt52_staging.py` (TXTSETUP rows, aliases,
  profile rows), `test_xp_user_settings.py` (2003 licensing, x64),
  pipeline tables, routing golden (additions only), BIOS command lines.
- XP x86 default: target digest identical to the previous package.
- Not run: BIOS VirtualBox install; X470 hardware.

ISOs: `pl_win_srv_2003_r2_enterprise_with_sp2_vl_cd1_x13-46476.iso`,
