# Sieć Intel I211 w Windows 7 / Server 2008 R2 — wstrzykiwanie sterowników z DATA

Data: 2026-10-22. Gałąź `ds/win7-net`, baza `test/x470-98se-qemu`
(`be1f36aa`). Cel: sprawdzić, jak instalator USOS wstrzykuje dziś sterowniki
z DATA, i doprowadzić do tego, żeby wystarczyło położyć rozpakowany folder
Intela (I211, `PCI\VEN_8086&DEV_1539`; `e1r62x86` / `e1r62x64`, NDIS 6.2).

Instrukcja dla użytkownika: [network-win7.md](network-win7.md).

## 1. Jak działa dziś (przed zmianą)

### 1.1 Windows 7 x86 / Server 2008 R2 x86 — CSMWrap (`win-x86-uefi-csmwrap`)

`tools/windows_x86_csmwrap.cmd`, krok `:usb3` (wywoływany po Setup
`/noreboot`, przed pierwszym rozruchem docelowego systemu):

| Co | Gdzie |
|---|---|
| brama: tylko NT 6.1 (7 / 2008 R2), Vista 6.0 i 8.x/10 pomijane | `tools/windows_x86_csmwrap.cmd:210-212` |
| DATA = pierwszy dysk z `Systems\Windows\Windows 7\` | `:213-215` |
| biblioteka x86: `…\Systems\Windows\Windows 7\Drivers\x86` | `:216` |
| szukanie `.inf` rekursywnie (`for /r`) | `:223-225` |
| brama KMDF 1.11 (MSU w `…\Windows 7\Updates`) | `:221`, `:230` |
| `DISM /Add-Package` KMDF | `:236` |
| `DISM /Add-Driver /Driver:"%USOS_DRV%" /Recurse /ForceUnsigned` | `:249` |

Czyli **rekursywny DISM `/Add-Driver` już był** — ale w środku kroku USB 3
i **za bramką KMDF**: brak `windows6.1-kb2864202-x86*.msu` (albo błąd
`Add-Package`) kończył krok (`goto usb3_done`) i **żaden sterownik nie był
dodawany**. Poza tym czytane było tylko drzewo biblioteki
`Systems\Windows\Windows 7\Drivers\x86`, a nie udokumentowany folder
użytkownika `DATA\Drivers\Windows 7` (`docs/drivers.md:1-18`).

**Odpowiedź na pytanie zadania (stan przed zmianą): NIE.** Folder
`Systems\Windows\Windows 7\Drivers\x86\e1r62x86\` był wprawdzie łapany przez
`for /r` (`:223`) i `/Recurse` (`:249`), ale tylko gdy na DATA leżał MSU KMDF
11.1 i jego `Add-Package` się udał; `DATA\Drivers\Windows 7\…` nie był czytany
wcale.

### 1.2 Windows 7 x64 / Server 2008 R2 x64 — natywne UEFI (wimboot)

Ścieżka UEFI (PE7 lub donor PE10), bez DISM w WinPE dla paczek użytkownika:

| Co | Gdzie |
|---|---|
| skan `DATA\Drivers\<wersja>` (katalog = jedna paczka, klasy `Storage`/`USB`/`Other`, korzeń = `Other`) | `src/platform/uefi/windows_user_drivers.zig:5-15`, `:147`, `:156` |
| walidacja INF (architektura amd64, `.cat`, `[SourceDisksFiles]`) | `src/platform/uefi/windows_user_drivers.zig:8-11` (`src/flow/inf_package.zig`) |
| paczki użytkownika do tego samego archiwum `usos-drivers.bin`, po bibliotece `Systems\Windows\Windows 7\Drivers\x64`, jako `user\<klasa>\NN\…` | `src/platform/uefi/windows_driver_files.zig:24-28`, `:31`, `:157`, `:199` |
| rozpakowanie archiwum do `usos-win7-drivers\…` w WinPE | `tools/windows_driver_archive.c:48-65` (`usos-drivers.exe`) |
| `DriverPaths` → `offlineServicing` / `Microsoft-Windows-PnpCustomizationsNonWinPE`, wpis `PathAndCredentials`, ścieżka = argument | `tools/windows_unattend_drivers.c:36-39`, `:111` |
| PE10 donor: `DriverPaths` = `usos-win7-drivers` (korzeń, zawsze) | `tools/windows7_modern_startup.cmd:56` |
| PE7 natywny z plikiem odpowiedzi: `DriverPaths` = `usos-win7-drivers` | `tools/windows7_native_startup.cmd:72-80` |
| PE7 natywny **bez** pliku odpowiedzi: `xcopy usos-win7-drivers\user` → `<dysk>:\USOS\Drivers` + `SetupComplete.cmd` | `tools/windows7_native_startup.cmd:100`, `:112-140` (`:128`, `:134`) |
| `pnputil -i -a` po każdym `*.inf` rekursywnie (`for /r`) w `Storage`/`USB`/`Other` | `tools/windows7_setupcomplete.cmd:12-14` |

**Odpowiedź dla x64: TAK.** Rozpakowany folder z `.inf` (amd64 + `.cat`)
położony gdziekolwiek w `DATA\Drivers\Windows 7\` jest jedną paczką
skanowaną rekursywnie, trafia do `usos-win7-drivers\user\<klasa>\NN\` i do
zainstalowanego systemu przez rekursywny `DriverPaths` (albo `pnputil` w
`SetupComplete.cmd`, gdy instalacja szła bez pliku odpowiedzi). Bez zmian
w kodzie — dowodem są wpisy powyżej i testy
`tools/tests/test_windows_driver_support.py`,
`tools/tests/test_windows7_user_drivers_setupcomplete.py`.

## 2. Co zmieniono (tylko x86 CSMWrap, tylko NT 6.1)

`tools/windows_x86_csmwrap.cmd`, krok `:usb3`:

1. **`DATA\Drivers\Windows 7` czytane także na x86** — litera dysku brana
   z DATA: `:217-219` (`for %%D in ("%USOS_DATA%") do set "USOS_USER_DRV=%%~dD\Drivers\Windows 7"`).
2. **Krok sterowników nie zależy już od KMDF** — brak MSU / brak CAB-a /
   błąd `Add-Package` daje tylko komunikat „…the driver packages are still
   added.” i przejście do `:usb3_drivers` (`:230`, `:234`, `:239`), zamiast
   `goto usb3_done`.
3. **Dwa rekursywne wywołania DISM**: biblioteka `Drivers\x86` pierwsza
   (`:249`), folder użytkownika druga (`:257`), każda z własnym logiem
   (`dism-drivers.log`, `dism-user-drivers.log`) i własnym `exit` w logu.
   Paczka obcej architektury w drugim drzewie nie zasłania pierwszej.
4. **`USOS_USB3_INSTALLED` nadal tylko z biblioteki `Drivers\x86`**
   (`:252-253`), żeby paczka sieciowa nie wyciszyła fallbacku `usosusb`
   (`:342`).

Zachowanie innych systemów bez zmian: krok nadal kończy się na
`if not "%USOS_NT%"=="6.1" exit /b 0` (`:212`), Vista (`:210`) i 8.x/10 nie
wchodzą do niego; ścieżka x64 nie jest dotknięta.

Test: `tools/tests/test_windows_x86_csmwrap.py` (sekcja po `:179`) —
sprawdza kolejność `/Add-Package` → `/Add-Driver`, bramę 6.1 przed DISM,
wyliczenie `USOS_USER_DRV`, dokładnie dwa rekursywne `/Add-Driver`
(`%USOS_DRV%`, `%USOS_USER_DRV%`), brak `goto usb3_done` przed sterownikami
i to, że `USOS_USB3_INSTALLED` ustawia tylko drzewo biblioteki.

## 3. Gdzie położyć paczkę Intela

* Windows 7 x86 / 2008 R2 x86:
  `DATA\Systems\Windows\Windows 7\Drivers\x86\e1r62x86\` (pewne, bo instaluje
  się pierwsze) albo `DATA\Drivers\Windows 7\e1r62x86\`.
* Windows 7 x64 / 2008 R2 x64: `DATA\Drivers\Windows 7\e1r62x64\`
  (albo `…\Other\e1r62x64\`).

Plików Intela nie ma w repozytorium i nie wolno ich commitować.

## 4. Jak sprawdzić instalację

Menedżer urządzeń (`Intel(R) I211 Gigabit Network Connection`, bez błędu),
`pnputil /enum-drivers` (`e1r62x86.inf` / `e1r62x64.inf`, klasa `Net`),
`ipconfig /all`, logi: `\USOS-usb3\dism-drivers.log` i
`dism-user-drivers.log` (x86), `usos-user-drivers.log` /
`\USOS\Drivers\usos-pnputil.log` (x64), `setupapi.dev.log`. Szczegóły:
[network-win7.md](network-win7.md).
