# Windows NT 3.x and Windows 3.x polish (2026-10-14)

Polish round for the NT 3.1 / 3.5 / 3.51 flow (docs/nt351-2026-10-08.md,
docs/nt35-2026-10-09.md, docs/nt31-2026-10-09.md) and the Windows 3.x flow
(docs/windows-early-2026-10-07.md), after the X470 hardware passes. Open
items from the X470 runs: no Polish characters, no user name / password /
automatic logon from the answer screen, VGA only, an empty-looking window at
the first logon.

## 1. Answer profile on NT 3.x: account, password, automatic logon

The answer screen already offered USOS profiles for every NT 3.x entry
(`answer_screen.profileCapable`, `answer/nt3.zig`), but the rendered
WINNT.SIF carried only the owner, organisation, computer name and time
zone: NT 3.x GUI Setup has no answer key for the Administrator password, an
own account or the automatic logon (INITIAL.INF: with `STF_GUI_UNATTENDED`
the password is always blank and the "local account" page is skipped).

Now:

| Profile field | WINNT.SIF line (nt3.zig) | Applied by |
|---|---|---|
| user name | `;USOS-USER=` | usosnt3.exe: `NetUserAdd` (level 1, password never expires) + `NetLocalGroupAddMember(Administrators)`; Winlogon `DefaultUserName` |
| password | `;USOS-PASSWORD=` | the same password for that account and for Administrator (`NetUserSetInfo` level 1003) |
| option "automatic logon" | `;USOS-AUTOLOGON=1` | Winlogon `AutoAdminLogon=1`, `DefaultPassword`, `DefaultDomainName` (the account domain from `LookupAccountName`: the computer name, the domain on NT 3.1 Advanced Server) |
| locale / keyboard | `;USOS-LOCALE=0000LLLL`, `;USOS-KEYBOARD=KKKKKKKK` | section 2 |

The `;USOS-` lines are INF comments, so Setup ignores them. micro-Linux
(`nt4_csmwrap_target.sh nt3_profile_files`) turns them into
`C:\USOS\NT3\ACCOUNT.TXT` and `INTL.TXT` and removes the account lines from
every WINNT.SIF copy on C:. usosnt3.exe reads them:

- NT 3.5 / 3.51: in the `usosnt3` service at the first start of the
  installed system inside the install VM (after the driver work, before the
  restart);
- NT 3.1 (no usosnt3 service): `POST.CMD` at the end of GUI Setup runs
  `C:\USOS\NT3\USOSNT3.EXE /polish`.

ACCOUNT.TXT is overwritten with zeros and deleted after use;
`nt4_vm_finish` deletes it too if it is still there. With the automatic
logon the password stays in the Winlogon `DefaultPassword` value, as on
every Windows with that option. Netapi calls go through `GetProcAddress`;
every static import of usosnt3.exe exists in the NT 3.1 kernel32/advapi32
(test_nt3_flow `test_usosnt3_imports_exist_on_nt31`). An own account named
Administrator or Guest is not created (the password goes to Administrator).
Without a profile nothing changes: Administrator with a blank password.

## 2. Polish characters (locale, keyboard, code pages, fonts)

All NT 3.x CDs in the library are English. Their international support is
complete enough for Polish on NT 3.51:

- every keyboard layout is copied by text-mode Setup (TXTSETUP.SIF
  `[Keyboard Layout]`: `00000415 = KBDPL1.DLL` Polish (Programmers),
  `00010415 = KBDPL.DLL` Polish (214));
- the code page files (`c_1250.nls`, `c_852.nls`, `c_10029.nls`) and, on the
  3.51 CD only, the Central European bitmap fonts (`vgasyse.fon`,
  `vgafixe.fon`, `sserifee.fon`, `couree.fon`, `serifee.fon`,
  `smallee.fon`, `vga852.fon`, `app852.fon`, ...) are installed;
- LANGUAGE.INF `[Options] 00000415 = locale.nls, 0415, 1250, 852, 10029`.

GUI Setup never switches the locale in unattended mode, so usosnt3.exe does
what LANGUAGE.INF `InstallOption` / LAYOUT.INF would do, from INTL.TXT:

- `Control\Nls\CodePage` `ACP=1250`, `OEMCP=852`, `MACCP=10029`, the file
  values and `OEMHAL=vga852.fon` (only when every code page file and every
  matching bitmap font is installed, else the code pages stay and only the
  locale and keyboard change);
- win.ini (registry-mapped) `[GRE_Initialize] FONTS.FON / FIXEDFON.FON /
  OEMFONT.FON`, the `[Fonts]` VGA-res bitmap fonts, `[FontSubstitutes]`
  `Arial CE = Arial` etc. (MakeFontEntries); system.ini `[386Enh]` WOA fonts;
- `Control\Nls\Language Default=0415`;
- in `HKU\.DEFAULT` and in the Default User hive (`config\userdef`, loaded
  with `RegLoadKey`): `Control Panel\International` `Locale` and the locale
  values from `GetLocaleInfoA` (NT 3.5+; NT 3.1 has only the W call, there
  only `Locale`), `Keyboard Layout\Active`.

The locale comes from the profile (locale / keyboard fields), else from the
menu language: the UEFI menu writes `locale=` / `keyboard=` into
`request.ini` (`win9x_preparation.formatRequest`, every answer) and
`w9x_nt3_ui_locale` adds them to the answer when it names none. A Polish
menu therefore installs NT 3.x with the Polish programmer's layout.

NT 3.5 and 3.1 CDs have the code page files and KBDPL1 but no CE bitmap
fonts: there the keyboard layout and locale change, the ANSI code page stays
1252 (Polish letters typed into ANSI programs become plain letters; Unicode
programs with a TrueType font show them where the font has the glyphs).

## 3. "Display Settings" at every logon (the empty-looking window)

NT 3.5x GUI Setup in unattended mode never runs the Display applet, so the
`Control\GraphicsDrivers\DetectDisplay` key from the default hive stays and
userinit.exe opens "Display Settings" at every logon (QEMU screenshots of
the 2026-10-12 NVMe runs show it behind Program Manager). usosnt3.exe
deletes the key. NT 3.1 has no such key.

## 5. Windows 3.1 / WfW 3.11

- **Polish keyboard:** the Polish 3.1 and WfW 3.11 Setup defaults to the
  typist layout (`defkeydll = poldll`, KBDPL.DLL). `windows_inf.bas`
  (W3INF.BAS, run by INSTALL.BAT before Setup) now switches it to the
  programmer's layout (`poldl1`, KBDPL1.DLL) when SETUP.INF lists one. Code
  page 1250 and the CE fonts were already installed by the PL editions. The
  English 3.11 and 3.0a have no Polish files (nothing to switch).
- **Resolution:** see the findings in section 6.
