# Windows 95 RTM/OSR1 LAN prerequisite — runtime pending

The existing NDIS 4 `usosnet4.sys` imports `NdisMSetAttributesEx` and
`NdisMSetPeriodicTimer`. Neither name occurs in the original RTM PL or OSR1
EN `NDIS.VXD` supplied for these tests. OSR2 evidence cannot certify either
older edition.

For a root SETUP version `4 0 0 950`, the target preparation now selects a
separate `network/win95-rtm/usosnet4.sys` and `usosnet95rtm.inf`. The installed
name remains `USOSNET.SYS`. Missing RTM inputs stop preparation. Other source
versions retain their previous package selection.

The separate build registers NDIS 3.0 with 60-byte characteristics and uses
the four-argument `NdisMSetAttributes` export. The timer uses `NdisSetTimer`
and rearms after serialized receive/transmit housekeeping; Halt cancels it.
Compile-time assertions check the generic/miniport timer prefix and EthDB
offset. Status indication calls remain exported functions rather than
new-header handler macros. The existing NDIS 4/5 binaries are not rebuilt.

`build_usosnet_rtm.py` uses the installed mingw-w64 DDK declarations, Zig cc
and GNU PE ld. Copied header corrections and all caches stay in its explicit
output directory. The PE32 native image has subsystem/OS version 4.0,
relocations, no CRT imports, no vector instructions, and 35 NDIS-only imports.
The 35 names occur in both original NDIS files. This is a name prerequisite
check, **not** proof of the export mapping, registration ABI, DHCP or runtime.

Host checks: 7 variant tests (binary/import contract, registration bytes,
actual staging/registry selection, missing-input stop, real timer callback),
11 existing Win95 network tests and 25 network-default tests pass. The latter
initially lacked the local Zig path; its affected build/render cases passed
after supplying `USOS_ZIG`. Only helper builds were run. No release build,
merge, push, deployment or physical-disk write.
